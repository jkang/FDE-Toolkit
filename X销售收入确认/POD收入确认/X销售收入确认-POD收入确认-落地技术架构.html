5 条链共享读写本体 / 按需调用 MCP
共享底座
🧱 本体（确定性底座）

读 R：交货单 / DN 全链路状态（POD 匹配）、签收有效性 / 对账状态（条件校验）、过账凭证 / 借贷项状态（查询）。
写 W：物流发运关联（邮件识别回写）、POD 确认 / POD 日志（确认写）、过账凭证 / 借贷项状态（过账回写）。
对象 / 关系 / 状态迁移 + 业务事实；五要素状态与规则校验走本体，不靠 LLM 猜事实。

🔌 MCP / 外部系统

调用点：SAP SD（交货单 / 预制发票 / 过账 / 凭证）、公共邮箱（邮件读取）、公共文件夹 / 文件服务（签收 / POD / 对账文件）、OCR / AI 识别服务、IM（待办与预警推送）。
仅需要外部读写的步骤才走 MCP。

📚 知识库 / RAG

检索点：对账差异规则库、POD 确认条件规则、承运商字典 / 发运单号规则、历史签收 / 自提样本。
规则校验走规则引擎而非向量检索；历史签收样本 / 非结构化知识走 RAG。

🩷 异常池（人工终审）：识别低置信度 / 关联冲突 / 对账口径冲突 / 超容差差异 / POD 条件缺口 / 过账失败 / Loop 超限 → 升级人工，附上下文摘要。

失败 / 降级 / 兜底

触发处理类型
SAP 交货单接口失败 / 超时重试 1 次 → 标记同步异常并通知 ITretry / escalate
邮件关键字段低置信度 / 冲突标黄转人工复核，补邮件留痕，不手工改写发运单号fallback / escalate
签收 / POD 识别置信度低标黄待人工复核字段，不阻塞其余字段fallback
对账差异口径冲突 / 无法归因转人工裁决 → 无法收敛升级 CS 经理 / 财务escalate
借贷项未过账阻断 POD 确认并生成待办，提示先完成借贷项fallback
POD 条件缺口阻断确认，列出缺口并引导补件 / 补对账fallback
SAP 过账失败记录返回信息 → 财务确认后手工重试，禁止无限制自动重试retry / escalate
超期阈值口径存疑拉人确认后回填配置escalate

KPI 锚定（链路 → 指标）

收入确认时效③ POD 确认 + ④ 过账　准实时 / 由人工 T+N 收敛
采集自动化率① 资料采集　自动拉取识别，人工工作量下降 70%+
对账差异处理效率② 对账差异　处理周期缩短 50%+
POD 确认合规率③ POD 确认　五要素硬校验 + 人工闸门
超期异常积压⑤ 驾驶舱预警　四类超期量下降 60%+

护栏落点

物流发运单号以邮件原文为唯一依据不开放手工直接改写；异常走补邮件 / 补充说明留痕
POD 确认是对外确认收入的强制人工闸门五要素任一不满足必须阻断，禁止系统自动确认
借贷项未完成不得放行 POD 确认借贷项状态为硬前置条件
过账失败不得无限制自动重试高风险财务动作，须财务确认后手工重试
确定性能力不交给 LLM五要素状态 / 规则校验 / 差异比对走本体与规则引擎
⚠️ 口径待确认：对账差异容差口径、POD 五条件判定口径、四类超期天数阈值需与业务确认后回填。
⚠️ MCP 边界：本方案把 SAP / 邮箱 / 文件服务 / OCR / IM 画成 MCP 外部调用；若确认「MCP=0，数据全部来自绑定本体」，则归入本体 / 内部服务并标 N/A。

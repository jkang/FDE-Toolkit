情境 1
交货单具备 POD 确认条件核验
CS 在 POD 匹配页面准备对一张交货单执行 POD 确认，需先确认五要素是否齐备
📋 Required Evidence
交货单表
交货单已同步且未取消
物流发运关联表
已建立交货单-发运单关联
POD资料表
存在有效签收资料或客户自提邮件确认，且非低置信度待复核
对账单表
对账状态为对账完成
借贷项表
差异借贷项已过账或不适用
✅ Valid Actions
汇总并展示五要素状态与匹配结论
校验 POD 确认条件并列出缺口
条件齐备时由 CS 一键 POD 确认并生成 POD 日志
条件不足时生成待办并引导补件/补对账
❌ Invalid Actions
在签收资料缺失或低置信度未复核时执行 POD 确认
原因：签收凭据是收入确认的审计依据，缺失即确认会造成审计风险
在对账差异或借贷项未完成时放行 POD 确认
原因：差异未清会导致收入金额不准确
绕过人工闸门由系统自动确认收入
原因：对外确认收入必须保留人工放行与责任留痕
⚠️ Exception Triggers
当：五要素存在缺口
→ 阻断确认，生成缺口待办并提示补件路径
当：特殊或异常场景需放行
→ 升级 CS 经理终审

# 业务本体：X销售收入确认-销售POD收入确认-Agent本体设计
领域：销售 / 收入确认
Agent 角色：销售POD收入确认助手（Sales POD Revenue Recognition Assistant）
场景：从 SAP 交货单采集、物流发运关联与签收资料识别，到对账差异处理、POD 确认、预制发票与财务过账的端到端收入确认场景

## 1. 核心业务对象与概念边界
### 交货单（Delivery Order / DN） [核心对象]
- 定义：SAP 交货单，是收入确认的业务主线与 POD 确认的颗粒度锚点
- 属性定义：
  * delivery_no (string) - SAP 交货单号 / DN
  * customer_code (string) - 客户编码
  * amount (number) - 交货金额
  * delivery_status (enum)（可选值：created / delivered / cancelled） - 交货状态
  * reconciliation_status (enum)（可选值：not_created / created / downloaded / feedback_uploaded / reconciled / difference） - 对账状态
  * pod_status (enum)（可选值：not_confirmed / pod_confirmed / confirm_failed） - POD 状态
- 关键概念边界（不可混淆）：
  ⚠️ 交货单已出库 ≠ 已取得有效签收凭据
  ⚠️ 交货单存在 ≠ 已完成对账或已 POD 确认
  ⚠️ 一张交货单可有多个 POD 资料，但只有 1 个最终 POD 确认
### 物流发运关联（Shipment Relation） [事件对象]
- 定义：交货单与物流发运单号的关联记录，来源于公共邮箱邮件的识别结果
- 属性定义：
  * delivery_no (string) - 交货单号
  * carrier_name (string) - 物流公司/承运商
  * shipment_no (string) - 物流发运单号
  * source_type (enum)（可选值：mail / manual_note） - 来源（公共邮箱 / 手工补充说明）
  * is_manual_modified (boolean) - 是否手工修改，原则上为否
- 关键概念边界（不可混淆）：
  ⚠️ 物流发运单号以邮件原文为唯一依据，不开放直接手工改写
  ⚠️ 已关联 ≠ 已签收
### POD 资料（POD Document） [事件对象]
- 定义：物流签收单、POD 文件或客户自提邮件，是收入确认所需的签收凭据
- 属性定义：
  * delivery_no (string) - 交货单号
  * document_type (enum)（可选值：sign_sheet / pod_file / self_pickup_mail） - 资料类型
  * sign_status (enum)（可选值：not_signed / pending / signed / self_pickup_confirmed / exception） - 签收状态
  * sign_time (datetime) - 签收时间
  * confidence (number) - 识别置信度
- 关键概念边界（不可混淆）：
  ⚠️ 识别成功 ≠ 签收有效，低置信度需人工复核
  ⚠️ 客户自提邮件确认视同物流签收，须归档邮件作为审计依据
### 对账单（Reconciliation Statement） [参考对象]
- 定义：按客户与周期汇总交货单、交客户确认的核对单据
- 属性定义：
  * statement_no (string) - 对账单号
  * period_from (datetime) - 对账周期开始
  * feedback_status (enum)（可选值：not_sent / sent / feedback_received） - 客户反馈状态
  * difference_status (enum)（可选值：none / pending / resolved） - 差异状态
- 关键概念边界（不可混淆）：
  ⚠️ 对账单已下载 ≠ 客户已确认
  ⚠️ 存在差异未清时不得标记对账完成
### 对账单明细（Reconciliation Line） [参考对象]
- 定义：对账单内逐交货单的数量与金额明细，是差异比对的载体
- 属性定义：
  * delivery_no (string) - 交货单号
  * sap_quantity (number) - SAP 数量
  * customer_quantity (number) - 客户确认数量
  * difference_type (string) - 差异类型
  * line_status (enum)（可选值：matched / difference / resolved） - 明细状态
- 关键概念边界（不可混淆）：
  ⚠️ 数量一致 ≠ 金额一致，需分别比对
  ⚠️ 差异归因结论必须逐条对应交货单
### 借贷项（Credit/Debit Item） [事件对象]
- 定义：对账差异处理后生成的借项或贷项调整
- 属性定义：
  * item_type (enum)（可选值：credit / debit） - 借项或贷项
  * amount (number) - 调整金额
  * posting_status (enum)（可选值：not_applicable / to_create / processing / posted / failed） - 借贷项过账状态
- 关键概念边界（不可混淆）：
  ⚠️ 借贷项未完成过账前不得开放 POD 确认
  ⚠️ 借贷项可由系统创建或仅记录状态，取决于确认口径
### POD 确认（POD Confirmation） [核心对象]
- 定义：以交货单/DN 为颗粒度的收入确认放行记录，是收入确认的关键闸门
- 属性定义：
  * delivery_no (string) - 交货单号
  * confirmation_status (enum)（可选值：not_confirmed / pod_confirmed / confirm_failed） - POD 确认状态
  * confirmation_time (datetime) - 确认时间
  * confirmed_by (string) - 确认人
  * prebill_no (string) - 预制发票号
- 关键概念边界（不可混淆）：
  ⚠️ POD 确认是对外确认收入的强制人工闸门，不得全自动放行
  ⚠️ 条件不齐备时系统必须阻断确认
### 预制发票（Pre-Invoice） [事件对象]
- 定义：POD 确认后由 SAP 自动生成的待过账发票
- 属性定义：
  * prebill_no (string) - 预制发票号
  * prebill_status (enum)（可选值：not_created / created / failed） - 预制发票状态
- 关键概念边界（不可混淆）：
  ⚠️ 预制发票由 POD 确认自动触发，财务页面不提供预制按钮
### 过账凭证（Accounting Voucher） [事件对象]
- 定义：财务过账后 SAP 返回的会计凭证信息
- 属性定义：
  * voucher_no (string) - 会计凭证号
  * posting_status (enum)（可选值：not_posted / posted / failed） - 过账状态
  * fiscal_period (string) - 会计期间
- 关键概念边界（不可混淆）：
  ⚠️ 过账失败不得自动无限重试，须财务确认后手工重试
### 文件资料（Attachment） [参考对象]
- 定义：原始资料、识别结果、补充附件、归档文件与预览地址
- 属性定义：
  * file_id (string) - 文件 ID
  * biz_object_type (string) - 业务对象类型
  * preview_url (string) - 预览地址
  * source_type (string) - 来源
- 关键概念边界（不可混淆）：
  ⚠️ 原始资料（邮件/签收单）与系统生成资料（POD日志/凭证）打印与归档规则不同

## 3. 行动边界限制（情境 - 证据 - 合法/禁止动作）
### 情境：交货单具备 POD 确认条件核验
描述：CS 在 POD 匹配页面准备对一张交货单执行 POD 确认，需先确认五要素是否齐备
必须核实的证据：
  - [交货单表] 交货单已同步且未取消
  - [物流发运关联表] 已建立交货单-发运单关联
  - [POD资料表] 存在有效签收资料或客户自提邮件确认，且非低置信度待复核
  - [对账单表] 对账状态为对账完成
  - [借贷项表] 差异借贷项已过账或不适用
✅ 合法动作（允许执行）：
  - 汇总并展示五要素状态与匹配结论
  - 校验 POD 确认条件并列出缺口
  - 条件齐备时由 CS 一键 POD 确认并生成 POD 日志
  - 条件不足时生成待办并引导补件/补对账
❌ 禁止动作（严禁执行，防范错误假设）：
  - 在签收资料缺失或低置信度未复核时执行 POD 确认 （禁止原因：签收凭据是收入确认的审计依据，缺失即确认会造成审计风险）
  - 在对账差异或借贷项未完成时放行 POD 确认 （禁止原因：差异未清会导致收入金额不准确）
  - 绕过人工闸门由系统自动确认收入 （禁止原因：对外确认收入必须保留人工放行与责任留痕）
⚠️ 异常触发规则：
  - 当满足条件【五要素存在缺口】 → 必须执行：阻断确认，生成缺口待办并提示补件路径
  - 当满足条件【特殊或异常场景需放行】 → 必须执行：升级 CS 经理终审
### 情境：物流发运关联的修正与留痕

⚠️ 异常触发规则：

    可用的状态转移路径：
      * --[识别签收/POD 资料或客户自提确认] (核实证据: 存在有效签收资料或客户自提邮件确认)--> 到达状态 签收有效 (性质: 正常迁移)

    可用的状态转移路径：
      * --[补邮件或补充说明后重新关联] (核实证据: 补充邮件/说明留痕且关联成功)--> 到达状态 物流已关联 (性质: 异常恢复)

    状态定义：已取得有效签收凭据，资料采集完成，可进入对账

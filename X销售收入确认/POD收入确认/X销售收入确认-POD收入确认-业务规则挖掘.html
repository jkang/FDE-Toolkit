物流发运关联匹配规则 使用点 · 识别邮件关键字段使用点 · 建立交货单-发运单关联
①决策因子
交货单号 / DN：邮件中出现的 SAP 交货单号 (来源 公共邮箱邮件正文/主题)
物流公司 / 承运商：邮件中的承运商名称 (来源 公共邮箱邮件 + 承运商字典)
物流发运单号：承运商开具的发运单号 (来源 公共邮箱邮件正文/附件)
邮件发件人与时间：判断邮件来源与时效 (来源 公共邮箱邮件头)
→
②逻辑分支
交货单号 + 发运单号唯一且承运商可识别 → → 自动建立交货单-发运单关联
一封邮件含多个交货单号 / 发运单号 → → 逐单拆分关联并标注一对多
发运单号缺失或格式异常 → → 转人工复核/补邮件
→
③分支动作
从公共邮箱邮件识别交货单号、承运商、发运单号并建立交货单-发运单关联。
→
④冲突仲裁
以邮件原文为唯一依据；同一交货单出现多条冲突发运单号时，取最新有效邮件并留痕。
例外/HITL：识别置信度低或存在冲突 → 拉人复核，物流补邮件/补充说明留痕，不开放手工直接改写。
对账差异规则 使用点 · 自动比对差异并归因
①决策因子
客户一致性：客户反馈中的客户与对账单客户是否一致 (来源 客户主数据)
交货单存在性：反馈中的交货单是否在 SAP 交货单范围内 (来源 SAP 交货单/明细)
数量一致性：SAP 数量 vs 客户确认数量 (来源 对账单明细)
金额一致性：SAP 金额 vs 客户确认金额 (来源 对账单明细)
反馈完整性：是否存在重复反馈或缺失反馈 (来源 客户反馈文件)
→
②逻辑分支
数量与金额均一致 → → 标记对账完成，进入 POD 确认
数量或金额不一致（在容差内） → → 标记差异并建议调整借贷项
交货单不存在 / 客户不一致 → → 标记异常并转人工核实
重复或缺失反馈 → → 提示去重/补全后重跑
→
③分支动作
按客户一致性、交货单存在性、数量/金额一致性、重复缺失与容差规则自动比对并归因。
→
④冲突仲裁
金额差异以 SAP 为准、数量差异以签收/对账确认为准；超容差差异必须人工裁决。
例外/HITL：文件格式不识别或口径冲突 → 拉人处理；差异无法收敛 → 升级 CS 经理/财务。
POD 确认条件规则 使用点 · 校验POD确认条件使用点 · 一键POD确认
①决策因子
交货单已同步：SAP 交货单已进入工作台 (来源 交货单表)
物流发运关联已建立：存在交货单-发运单关联 (来源 物流发运关联表)
签收/POD 有效：存在有效签收资料或客户自提确认 (来源 POD资料表)
对账已完成：对账单状态为对账完成 (来源 对账单表)
借贷项已完成或不适用：差异借贷项已过账或无差异 (来源 借贷项表)
用户具备 POD 确认权限：当前用户角色与数据范围 (来源 权限服务)
→
②逻辑分支
五要素全部满足 → → 允许 POD 确认（人工闸门放行）
存在条件缺口 → → 阻断并提示缺口，生成待办
特殊/异常场景 → → 转 CS 经理审批
→
③分支动作
五要素硬校验，全部满足才允许人工一键 POD 确认。
→
④冲突仲裁
任一硬条件不满足一律阻断；借贷项未完成优先于其它条件阻断。
例外/HITL：条件缺口 → 引导补件/补对账；特殊场景 → CS 经理终审。
超期异常阈值规则 使用点 · 更新驾驶舱与超期预警
①决策因子
已发货未取发运单天数：交货单出库后未关联发运单的持续天数 (来源 交货单表 + 物流关联表)
已取得未签收天数：已关联发运单但未取得有效签收的持续天数 (来源 物流关联表 + POD资料表)
已发货未创建对账单天数：交货单出库后未创建对账单的持续天数 (来源 交货单表 + 对账单表)
具备条件未 POD 确认天数：条件齐备但未 POD 确认的持续天数 (来源 POD匹配表)
→
②逻辑分支
未超配置阈值 → → 正常展示待办
超过预警阈值 → → 黄色预警并推送待办
超过严重阈值 → → 红色预警并升级责任人/经理
→
③分支动作
按可配置阈值计算四类超期异常并驱动驾驶舱预警与待办推送。
→
④冲突仲裁
阈值按业务配置，口径存疑时以业务确认值为准；四类异常独立计算不合并。
例外/HITL：阈值口径存疑 → 拉人确认后回填配置。

使用点 · 创建对账单使用点 · 下载对账单交客户确认
固定骨架（章节 / 表头）
① 对账单头
固定：固定栏（对账单号/客户编码/客户名称/对账周期/币种/生成人/生成时间）
动态：随创建参数动态填充
② 交货单明细
固定：固定栏（交货单号/出库日期/数量/金额/对账状态）
动态：随勾选交货单动态填充
③ 汇总与差异
固定：固定栏（合计数量/合计金额/差异金额/借贷项状态）
动态：随差异分析结果动态填充
动态字段来源
对账单号 ← 系统按规则生成（如 RC-2026-09-001）
对账周期 ← 来自 CS 选择的起止日期
客户名称 ← 来自客户主数据
生成规则：存在 SAP 交货单才可创建；按客户与周期批量创建，一张对账单对应多张交货单。 合规：下载给客户的对账单必须含客户、周期、交货单明细与合计金额；缺一不可。
典型 · 单客户单周期对账 · 交货单齐全，差异为零，客户一次确认通过 反面 · 含未同步交货单 · 未同步交货单不得入对账单，否则差异无法归因

使用点 · 下载对账单交客户确认使用点 · 确认差异并处理借贷项
固定骨架（章节 / 表头）
① 反馈头
固定：固定栏（对账单号/客户/反馈日期/反馈人）
动态：随客户反馈文件动态填充
② 明细差异
固定：固定栏（交货单号/SAP数量金额/客户确认数量金额/差异）
动态：随客户反馈数据动态填充
③ 差异说明与处理
固定：固定栏（差异类型/原因/借贷项处理结论）
动态：随 CS 处理结果动态填充
动态字段来源
差异类型 ← 来自对账差异规则归因结果
借贷项处理结论 ← 来自借贷项处理状态
生成规则：客户反馈上传后自动解析生成差异说明；人工确认差异原因后回写结论。 合规：差异说明必须逐条对应交货单并给出处理结论，未清差异不得标记对账完成。
典型 · 数量差异 · 客户少计一箱，生成借项并完成过账后对账完成 反面 · 差异未说明 · 存在差异但无原因与处理结论，禁止进入 POD 确认

Proof of Delivery，签收凭据（物流签收单 / 客户自提确认）

PID
价格审批单，其审批结果生成价格条件作为 SO 基准
适用：POD确认与开票口径
借贷项
对账差异处理后生成的借项或贷项调整
适用：差异与借贷项处理

POD 确认后由 SAP 自动生成的待过账发票
适用：预制发票与过账

适用：发票过账

适用：对账单处理

适用：签收确认

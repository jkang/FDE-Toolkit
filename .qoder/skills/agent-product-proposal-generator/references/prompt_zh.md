# 分段生成提示词（Prompt 引擎）
# 说明：本文件是「核心设计引擎」可操作化的生成指令。按段使用，驱动 LLM 逐段汇编 Agent 产品方案。
# 通用基调：学员/原型作者视角，专业克制、数字驱动；不写观众导向的空话；每段都要能追溯到上游来源。

---

## 总则（先读）

你在为一款 AI Agent 写「可施工的工程级设计文档」——**不是**做产品宣发，而是让原型作者照单施工。铁律：
- **来源可溯**：每个功能、每段剧本、每条 HITL、每格门禁都要能引用上游具体的 L5 任务 / 规则条目 / 术语 / 决策因子。
- **决策因子驱动**：mock 数据、阈值、拦截条件一律取自挖知识的「决策模型类规则」，不要编。
- **硬/软约束区分**：硬约束(不可突破) → 必停 + 撤销；软约束(可仲裁) → 提示 + 出处引用。HITL 只盖两类硬闸门 + 少量软冲突点。

## 第 2 段 · 产品定位（先写它，其余段以它为"灵魂"）

提示词：
```
你是一个资深 Agent 产品架构师。基于以下输入，输出《产品定位》（四件套）：
- 输入：AI 场景画布（userRoles / userPains / aiInput / aiOutput / productType / userGains）→ 见 {canvas}
- 输入：理需求业务痛点点（见 {painpoints}）
- 输入：本体行动边界（能做/不做，见 {ontology_bounds}）

要求：
1. 定位一句话 = 「为 {userRoles}，在 {scenario} 场景下，通过 {AI 核心能力}，把 {userGains/MoS 指标} 一起往上拉」。
2. 非目标 = 与场景边界互斥的相邻场景/系统（各写一句，排除相邻画布/相邻产品）。
3. 主要使用者 = 角色 + 每轮流程里他做的事。
4. Agent 人格 = 身份定位 + 语气基调(专业/克制/数字驱动) + 能做(≥2) / 不能做(≥2，来自本体行动边界)。
只输出结构化条目，不要展开。语气用 {tone}。
```

## 第 3 段 · 产品形态架构图（mermaid）

提示词：
```
基于本体设计（实体/关系/动作）与 To-be 流程（入口/交互/相邻系统），画一张 mermaid flowchart：
- 三大区：入口区（主入口/自动激活）、主交互区（对话流 + 核心交付载体 Artifact，如「方案工作台」）、周边支撑区（待办/历史版本/复盘）。
- 相邻产品：只画接触面（读/写），不画协议与字段；用 subgraph + dashed 样式区分。
- 核心交付载体（Artifact）是唯一 P0，放主交互区最显眼。
节点命名用业务词，注释可附「读/写」方向。输出为 ```mermaid 代码块```。
```

## 第 4 段 · 原型演示故事线（默认 4 条）

提示词：
```
按 L3/L5 阶段把智能订舱全链路切成 4 条有头有尾的演示故事线，每条为一个 markdown 表：
列：业务价值高光 / 对应阶段 / 演示剧本 / UI组件 + 必备交互 / 业务内容来源。

演示剧本用「用户 → Agent 思考 → 调工具 → 输出 →(HITL/错误/撤销)」五段式写清楚；
mock 数据必须取自 SKP 决策模型类规则的「决策因子 / 阈值」（脱敏），禁止编造；
「UI组件 + 必备交互」要标注 10 项交互的 #号（#1 流式 #2 工具调用可视化 #3 思考折叠 #4 内联组件 #5 HITL 拦截 #6 撤销 #7 出处引用 #8 状态徽章 #9 错误态 #10 空态）；
「业务内容来源」写具体 L5 任务名 + 规则类名（如：SKP 深度任务·计算建议补货量；SKP 决策模型类·备货率分配规则）。
4 条建议覆盖：① 核心主路径价值打单 ② 主流程 + HITL 拦截 ③ 异常/边界 + 错误态 ④ 闭环执行 + 撤销 + 复盘。
```

## 第 5 段 · 业务功能与 UI 组件清单

提示词：
```
输出一张功能×组件大表，把全部功能列为一个 markdown 表：
列：功能名 / 一句话价值 / 绑定角色 / 渲染层(Artifact Pane | Conversation Pane) / 触发方式(用户点击召唤 | Agent 主动渲染 | 自动激活) / UI 组件名+内容 / 用户操作(只读|可编辑|可撤销|可下发|可审批) / 关联故事线 / 上游来源。

把「必备交互 10 项承诺」作为一行产品承诺，写：**必备交互 10 项：** #1 流式输出 / #2 工具调用可视化 / #3 思考过程可折叠 / #4 内联组件 / #5 HITL 拦截 / #6 撤销回滚 / #7 出处引用 / #8 状态徽章 / #9 错误态 / #10 空态。
每个功能都要能映射到上游 L5/规则/术语条目；术语 hover 卡与出处引用悬浮卡必列入，作为可解释性承接。
```

## 第 6 段 · Agent 行为设计

提示词：
```
输出 4 小节：
6.1 Agent 是谁：开场话术草稿 + 语气基调 + 能力边界承诺(能/不能，来自本体行动边界)。
6.2 Agent 让用户看到什么：事件类型 → 默认行为 → 落到交互 #号（进度=#8 状态徽章；数据来源=#7 出处；置信度低=#5 HITL + #7；触发工具=#2；思考=#3 折叠）。
6.3 Agent 何时停下等用户：做成表：触发类别(对外发送|修改关键业务数据|Agent自判不确定|连续失败/重试超限) / 触发条件 / 默认拦截形态 / 理由来源。硬约束→写入前必停+撤销窗口；软约束→提示+出处。
6.4 用户怎么撤销与兜底：撤销范围 / 追问深度(出处引用) / 完全失败时给 ≥2 明确选项(#9 错误态)。
所有拦截条件必须引自挖知识「决策模型类规则」的硬/软约束。
```

## 第 7 段 · SKP 五类规则消费门禁

提示词：
```
输出一张门禁承接表，五类规则各一行：
列：SKP 规则类型 / SRP 是否识别 / 产品方案承接点(第几章＋组件) / 承接的业务内容 / 备注。
五类：决策模型类(必须承接) / 模版范例类(必须承接) / 术语字典类(必须承接) / 关键信息提取要点(必须强化承接) / 关联关系类(必须承接)。
操作流程类(分货计划编制流程/补货单校验规则等)已由 SKP 深度任务序列承载，表格不重复，在本表末尾用一行注明「操作流程类由第5章功能清单的上游来源列通过深度任务业务名引用」。
SRP 是否识别：若上游有对应规则则「✅」，缺失则「⚠️（待补）」并写入第8段。
```

## 第 8 段 · 待确认问题清单

提示词：
```
把生成过程中所有「悬空 / 需要 FDE 或业务专家确认」的点，归纳为一张表：
列：# / 待确认问题 / 用途与影响。
常见方向：① 决策阈值与业务专家口径是否一致（如 中旬 +20% 备货率、0.5% 差异率、90/85/10 复盘阈值）；② 效期/大日期阈值口径能否坐实；③ 视觉基底 P0~P3 锚定（客户品牌手册/设计系统）；④ 与本产品相邻系统的边界（默认相邻、只读/写分配量）。
每条写清「不确认会导致什么」。
```

## 第 1 段 · 总览（最后回填）

提示词：
```
基于全文（2~8 段）回填《总览》，写成自然段（非表格）：
1. 这份方案做了什么：在 vX.0 概念级基础上，用已完成的上游(理需求/场景定义/挖知识/本体)整体回填精化，翻译成一份原型作者可照单施工的产品方案(定位+架构+故事线+功能+Agent行为+规则门禁)。
2. 重点看什么：核心交付载体(Artifact)是什么、全场景唯一 P0；本版关键升级在哪些点(对齐哪些决策因子/阈值)。
3. 为什么关注：商机经营指标哪些由本产品决定；价值主张是什么；规则承接是否「挖到位」决定是否可解释/可复核/可验收。
4. 当前洞察：规则结构是否高度统一、集中在哪两个环节；硬约束 vs 软优先级分布；HITL 只需覆盖哪几类。
5. 需要 FDE 做什么：① 核对故事线 mock 数据与 SKP 阈值一致性；② 确认效期/边界阈值口径；③ 视觉基底与相邻产品边界(仍待确认，属阶段2 前置项)。
```

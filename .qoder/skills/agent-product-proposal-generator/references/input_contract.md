# 上游输入契约（Input Contract）
# 说明：本 Skill 消费 FDE 方法「理需求 / 场景定义 / 挖知识 / 梳理本体」的既有产出。
# 每个输入文件需用 Read 读取其中的关键字段，映射到 Agent 产品方案的对应段落。
# 缺失项允许「降级」：用现有产出代理，并在文档 meta.input_sources 中显式标注「用哪份代理」。

---

## 1. 理需求（业务与价值定位）

**上游产物**：企业画像 / 业务现状全景 / 需求场景全景（或 NSM 分析 / 业务流程深度分析 / 体验旅程图 / 服务蓝图）。

**关键字段 → 本 Skill 用途**：

| 关键字段 | 映射到 |
|---|---|
| 业务领域 / 价值流 | 第2段·迭代范围、第2段·产品形态 |
| 业务痛点 / 证据 | 第2段·定位一句话、第4段·每条故事线的业务价值高光、第1段·为什么关注 |
| 端到端流程 / L2 蓝图 | 第3段·相邻产品接触面、第5段·功能 |

**降级规则**：若只有「业务流程深度分析」而无「需求场景全景」，用其价值流/痛点代——仍可产出定位与非目标，value 高光需标注「基于流程推断」。

---

## 2. 场景定义（场景与边界）

**上游产物**：AI 场景画布（AI Canvas，10 维）+ 数据/知识资产盘点（CKD）。

**关键字段 → 本 Skill 用途**：

| 关键字段 | 映射到 |
|---|---|
| userRoles / userPains | 第2段·主要使用者、第2段·定位一句话、第2段·Agent 人格语气 |
| aiInput / dataKnowledge | 第3段·主交互区（输入/知识）、第4段·演示剧本 mock、第5段·功能 |
| workflow / modelUsage | 第3段·编排、第6段·让用户看到什么（工具调用） |
| aiOutput / tools | 第4段·Agent 输出、第5段·UI 组件 |
| productType / userGains(MoS) | 第2段·产品形态、第2段·定位一句话、第1段·为什么关注、第4段·业务价值高光（KPI） |
| 场景边界 / 相邻系统 | 第2段·非目标、第3段·相邻产品 |

**降级规则**：若缺「数据/知识资产盘点」，则由 CKD 映射或本体数据字段代，功能清单的「上游来源」标注「依据画布字段推断」。

---

## 3. 挖知识（规则与约束——本 Skill 的动力源）

**上游产物**：任务流程挖掘清单（L3→L4→L5 深度任务）+ 任务处理规则挖掘清单（五类规则）+ To-be 流程 / CKD 映射 / Agentic 工作流。

**关键字段 → 本 Skill 用途**：

| 关键字段 | 映射到 |
|---|---|
| L5 深度任务（actor：agent/mixed/human） | 第4段·故事线按阶段切分、第5段·功能上游来源、第3段·交互编排 |
| 决策模型类规则（决策因子 / 阈值 / 优先级） | 第4段·演示剧本 mock、第6段·HITL 触发、第7段·门禁表 |
| 硬约束（不可突破：可发量/对外下发/负量） | 第6段·何时停下（写入前必停 + 撤销）、第7段·门禁 |
| 软约束（可仲裁：成本优先/配送时效） | 第6段·何时停下（提示 + 出处引用）、第7段·门禁 |
| 模版范例类（表单/报告模板、必填字段） | 第5段·功能 UI 组件、第7段·门禁 |
| 术语字典类 / 关键信息提取要点 | 第5段·术语 hover 卡、第7段·门禁（必须强化承接） |
| 关联关系类（实体关联网络） | 第3段·接触面、第7段·门禁 |
| Agentic 工作流（活动序列/编排模式/护栏/失败兜底） | 第6段·让用户看到什么、第6段·撤销与兜底 |

**降级规则**：若缺「任务处理规则挖掘清单」，可用 L5 任务表的 `ruleType` 列 + 决策因子作代理，门禁表标注「基于任务表推断」，并把「需要 FDE 确认」写入第8段。

---

## 4. 梳理本体（Agent 的结构与行为边界）

**上游产物**：Agent 本体设计（对象关系 → 行动边界 → 状态迁移）+ Agentic 工作流（若分开）。

**关键字段 → 本 Skill 用途**：

| 关键字段 | 映射到 |
|---|---|
| 对象（实体）/ 关系 | 第3段·主交互区、第3段·相邻产品接触面、第5段·功能 |
| 行动边界（能做/不做、HITL 门） | 第6段·Agent 能力边界、第6段·何时停下、第4段·HITL 拦截 |
| 状态迁移（状态机：待装柜/已开船/待补件…） | 第5段·状态徽章(#8)、第4段·故事线状态流转 |
| HITL 边界 / 防旁路 | 第6段·何时停下（必停）、第5段·HITL 拦截(#5) |

**降级规则**：若缺「本体设计」，用 To-be 流程/SRP 边界代，第6段能力边界标注「依据流程推断」，并纳入待确认。

---

## 5. 输入清单读取顺序（SOP 第 1~2 步）

建议按「本体 → 挖知识 → 场景定义 → 理需求」顺序读取（先取深/近边界，再取价值/定位），用临时文件传递中间结果：
1. 本体：抽取实体/动作/HITL/状态 → 决定第3段、第6段骨架。
2. 挖知识：抽取 L5/规则/因子/硬软约束 → 决定第4、5、7段骨架。
3. 场景定义：抽取画布字段/MoS → 决定第2段四件套、第4段价值高光。
4. 理需求：抽取价值流/痛点 → 补齐第2段、第1段。

任何一步缺文件 → 中止并向用户确认，或降级后写入第8段「待确认问题」。

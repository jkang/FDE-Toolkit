舱位推荐排序规则 使用点 · 综合排序推荐 Top3
①决策因子
装载率（Load Factor）：航次已订舱量占可用舱位的比例 (来源 舱位收益系统)
ETA 置信度：预计到港时间（ETA）预测的置信度 (来源 ETA 预测模型)
舱位保证（Space Guaranteed）：该航次是否提供舱位保证承诺 (来源 舱位管理)
→
②逻辑分支
有舱位保证 + 高 ETA 置信度 → → 置顶推荐并附舱位保证条款
装载率高但 ETA 置信度低 → → 降序推荐且标注置信度
旺季舱位挤兑、舱位保证可能违约 → → 前置预警 + 给改配方案
→
③分支动作
按装载率/ETA 置信度/舱位保证综合排序，生成可解释的 Top3 舱位推荐。
→
④冲突仲裁
舱位保证 ＞ ETA 置信度 ＞ 装载率；旺季挤兑时预警优先于常规排序。
例外/HITL：ETA 置信度低于阈值 → 降级为提示，不作为确定性推荐依据
订舱校验规则引擎 使用点 · 订舱规则校验
①决策因子
费率：报价单全包价与订单费率一致性 (来源 报价引擎)
信用：货主授信额度与信用状况 (来源 信用系统)
航线可用性：航线/船期在订舱窗口内是否可用 (来源 船期系统)
→
②逻辑分支
费率不一致 → → 拦截并标注原因，提示补正
信用受限（超出授信） → → 提示补正/转人工终审
航线在窗口内不可用 → → 建议邻近航线（Nearby Route）
→
③分支动作
运行 200+ 条订舱校验规则，识别费率/信用/航线三类异常，作提交前确定性校验。
→
④冲突仲裁
信用受限或费率不一致者不得放行；全部通过后才可进入人工确认门禁。
例外/HITL：校验不过/信用受限 → 标注原因并提示补正/转人工终审
新客首单预填兜底规则 使用点 · 3 步表单自动预填
①决策因子
是否历史货主：有无历史订单数据（订舱记录） (来源 CRM/OMS)
会话上下文：本次会话已确认的要素（港口对/箱型/品名） (来源 会话内存)
贸易单据 OCR：PI/装箱单抽取的字段与置信度 (来源 OCR 解析器)
→
②逻辑分支
有历史数据 → → Smart Push 画像预填
新客无历史数据 → → 会话上下文 + PI/装箱单 OCR 兜底预填
OCR 置信度低 → → 标黄待人工复核/追问补录
→
③分支动作
针对新客无历史数据的首单，用会话与贸易单据 OCR 兜底预填订舱表单，杜绝空预填。
→
④冲突仲裁
历史画像优先；无画像则走 OCR 兜底；字段不可确定时明示置信度而非静默填。
例外/HITL：新客无历史数据 → 会话+OCR 兜底预填，标注置信度
单证校验规则（含 VGM/毛重差异） 使用点 · 单证规则校验
①决策因子
VGM 申报：核实的集装箱总重是否申报 (来源 智慧单证系统)
毛重差异：SI 毛重与装箱单/称重差异是否超限 (来源 智慧单证系统)
HS 编码：品名能否映射到合规 HS 编码 (来源 多语言品名/HS 字典)
→
②逻辑分支
VGM 缺失 → → 生成补全项 + 填写示例
毛重差异超限 → → 差异告警，提示一次补全
HS 编码无法映射 → → 提示人工复核，禁止猜测
→
③分支动作
运行 300+ 条单证规则，处理 VGM 缺件/毛重差异/HS 编码三类异常，禁止带缺件推送。
→
④冲突仲裁
VGM 缺失/毛重超限者阻止推送；HS 无法映射走人工复核，不阻塞主链路。
例外/HITL：VGM 缺失/毛重超限 → 生成补全项；HS 无法映射 → 人工复核
延误处置与售后分级规则 使用点 · ETA 预测与延误预警使用点 · 复杂问题转人工附摘要
①决策因子
延误概率：ETA 预测模型输出的延误概率 (来源 ETA 预测模型)
风险分级：高风险延误（甩柜/改船）vs 常规延误 (来源 控制塔运营)
情绪/投诉级别：对话情绪与投诉严重度 (来源 情感识别模型)
→
②逻辑分支
延误概率高（如 >60%） → → 事前预警 + 订阅通知
高风险延误（甩柜/改船） → → 升级人工按 Delay in Transit 出改配/赔付
复杂投诉/情绪激动 → → 附完整上下文摘要升级人工
→
③分支动作
按延误概率与风险分级决定预警强度，复杂售后附上下文摘要升级人工。
→
④冲突仲裁
高风险延误 / 投诉升级优先于常规播报；ETA 置信度低时降级为事后通知。
例外/HITL：甩柜/改船 → 人工出改配与赔付；复杂投诉 → 附摘要转人工；低置信度 → 降级通知

Booking Confirmation 订舱确认书模板
使用点 · 签发 Booking Confirmation
固定骨架（章节 / 表头）
① 订舱信息
固定：固定栏（Booking 编号/船名航次/起运港/目的港/箱型/数量/ETD）
动态：随订舱请求动态填充
② 费用与条款
固定：固定栏（全包价/有效期/舱位保证 Space Protection 条款）
动态：随报价单动态填充
③ 双方信息
固定：固定栏（货主/订舱方/联系方式）
动态：随会员画像填充
动态字段来源
Booking 编号 ← 来自 OMS 受理结果（如 BK-2026-0901-001）
全包价 ← 来自报价单 all_in_price
舱位保证条款 ← 来自舱位管理 Space Guaranteed 承诺
生成规则：标准单自动确认；复杂单须人工终审后才可签发。 合规：对外通知必须含订舱编号、船期、全包价三项关键信息；缺一不可。
典型 · 标准订舱确认 · 字段齐全，最快 1 分钟自动签发并多渠道通知货主 反面 · 缺订舱编号/全包价 · 禁止缺关键字段即签发，否则下游无法履约与结算
转人工上下文摘要模板
使用点 · 复杂问题转人工附摘要
固定骨架（章节 / 表头）
① 对话摘要
固定：固定节（用户目标/已提供信息/未决问题）
动态：随会话动态生成
② 货主画像
固定：固定节（PlumSmart 等级/历史订舱/当前订单）
动态：随会员画像填充
③ 建议动作
固定：固定节（推荐处理/风险提示）
动态：随意图与风险分级生成
动态字段来源
对话摘要 ← 模型对多轮会话的摘要
货主画像 ← CRM 会员画像（PlumSmart）
建议动作 ← 意图识别 + 情感/风险分级
生成规则：复杂问题必须附完整上下文摘要，避免人工重复收集信息。 合规：情绪激动/投诉类置顶转人工；摘要不得含未脱敏敏感信息。
典型 · 复杂投诉摘要 · 摘要 + 画像 + 建议动作齐全，客服直接接手一次性解决 反面 · 只给对话原文 · 禁止只甩对话原文，否则人工需重读全文、重复提问

智能订舱业务口径词典 使用点 · 报价逐项解读使用点 · 单证规则校验使用点 · D&D 规则智能解读
全包价 All-in Price
含运费+附加费+杂费的单一报价
适用：报价逐项解读
舱位保证 Space Guaranteed
舱位管理方对特定航次的保证承诺（含 Delay in Transit 保障）
适用：综合排序推荐
Booking 编号
订舱确认书的唯一编号（如 BK-2026-0901-001）
适用：订舱受理/签发
D&D
免箱期外的滞箱费/滞港费（Demurrage & Detention）
适用：D&D 规则解读
免箱期
免费用箱天数窗口（各目的港政策不同）
适用：超期预警
VGM
核实的集装箱总重（Verified Gross Mass）
适用：单证校验
SI
装运指示（Shipping Instruction）
适用：单证预填
eBL
电子提单（Electronic Bill of Lading）
适用：单证进度
维护方：订舱运营/单证团队，随口岸政策与费率规则更新
引用范围：报价解读、订舱校验、单证校验、D&D 解读、出运跟踪

货主—报价—订舱—单证—跟踪关联 使用点 · 综合排序推荐 Top3使用点 · 订舱规则校验使用点 · OCR 抽取 SI 字段使用点 · 对话查里程碑
货主ID↔报价单↔订舱请求↔订舱确认书↔SI/舱位
用货主 ID 贯通报价与会员画像；用订舱请求关联报价与订舱确认书（Booking 编号）；用舱位约束订舱确认的签发与舱位保证兑现；用 SI 关联单证进度。
建立规则货主ID 关联 CRM 画像与报价单；订舱请求触发订舱确认书（Booking 编号）；舱位分配约束订舱确认签发与舱位保证兑现；SI 关联订舱确认书
特殊情况一张报价单可触发多次订舱请求（货主改方案）；一份订舱确认书对应多份 SI；同订舱可能拆分多箱需按箱级追踪

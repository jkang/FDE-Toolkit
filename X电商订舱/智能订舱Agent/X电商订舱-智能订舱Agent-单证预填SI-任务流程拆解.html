「SI 字段生成与单证校验」仍然太粗

它包含 OCR 抽取、品名规范、HS 映射、单证校验、补件等不同动作，输入输出和异常各不相同，不能直接作为最小执行单元。

OCR 抽取 SI 字段
🤖 Agent 		贸易单据（PI/装箱单/发票 PDF/图片/Excel） 抽取的 SI 字段（品名/唛头/件数/毛重/体积）+ 置信度标注 关键信息提取要点·SI 字段抽取与置信度判定 OCR 置信度低（模糊/破损）→ 标黄待人工复核，不阻塞其余字段
品名规范与 HS 映射
🤖 Agent 		抽取的品名/唛头/件数 + HS 映射字典 标准化品名 + 合规 HS 编码 术语字典类·多语言品名/HS 编码映射 HS 编码无法映射 → 提示人工复核（禁止擅自猜测）
单证校验与补件
🤖 Agent 		SI 字段 + 单证规则库（>300 条） 校验结果（含 VGM/毛重差异告警）+ 补全项示例 决策模型类·单证校验规则（VGM/毛重/HS） VGM 缺失/毛重超限 → 生成补全项；异常未修正 → 阻止提交
🔁输入输出如何闭环 下游衔接
订舱确认书（已签发） → 上传贸易单据 → OCR 抽取 SI 字段 → 品名规范 + HS 映射 → 单证校验（VGM/毛重/HS） → 确认提交 SI → 下游：推送单证系统 → 进入提单流程
💡挖掘的关键

为什么这样拆？

三个动作各自只有一个核心动词，产出可观察，并可独立挂接规则（提取要点 / HS 字典 / 单证校验规则）。

挖掘的关键不是改写名称

挖掘的关键不是改写名称，而是把单证预填这一真实执行的动作顺序、输入输出、判断依据（VGM/毛重/HS）和异常链路（标黄/补件/人工复核）结构化，供 P2 规则绑定与下游本体/测试消费。

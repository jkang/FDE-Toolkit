SME 货主通过对话式智能订舱 Agent 完成询价、舱位推荐、订舱确认、单证预填与出运跟踪的端到端场景

实体（Entities）

实体类型：
核心对象（core）— Agent 直接操作或判断的实体
参考对象（reference）— 提供上下文或约束
事件对象（event）— 记录业务发生的事件
核心对象
订舱请求（Booking Request）

货主经确认后向系统提交的订舱意向，是订舱链路的触发对象，不等于已获舱位

status enum
draft / validated / submitted / confirmed / voided
container_type string
箱型（如 40HQ）
port_pair string
起运港-目的港港口对
⚠️ 概念边界
≠ 订舱请求已提交 ≠ 已签发 Booking Confirmation（可能被校验驳回）
≠ 订舱请求的状态不等于舱位状态，须以 Booking Confirmation 为准
核心对象
订舱确认书（Booking Confirmation）

确认已分配舱位并对外承诺的正式文件，含 Booking 编号与舱位保证，是后续单证与跟踪的锚点

booking_no string
订舱编号（如 BK-2026-0901-001）
space_guaranteed boolean
是否含舱位保证（Space Protection / Delay in Transit）
confirmed_at datetime
签发时间
⚠️ 概念边界
≠ Booking Confirmation 是最快 1 分钟能签发的确定性文件，与报价单（Query）不同
≠ 舱位保证承诺 ≠ 实际已装载，违约时触发赔付流程
参考对象
报价单（Quotation）

报价引擎生成的 E-Spot/E-Quote 报价，含全包价构成与有效期，可锁定（Secured）

quote_type enum
e_spot / e_quote / secured_e_quote
all_in_price number
全包运价（USD）
validity datetime
有效期
⚠️ 概念边界
≠ 报价单只是价格意向，不等于已锁定舱位或已订舱
≠ Secured E-Quote 锁价 ≠ 已签发订舱确认
核心对象
装运指示（SI）

货主提交的装运指示单证，含品名/唛头/件数/毛重/体积/HS 编码，是提单签发的依据

status enum
draft / extracted / validated / submitted
hs_code string
HS 编码
vgm number
VGM 核实的集装箱总重
⚠️ 概念边界
≠ OCR 抽取的 SI 字段 ≠ 已通过规则校验（可能有 VGM 缺件）
≠ SI 校验通过 ≠ 已签发提单，需再进入提单流程
参考对象
贸易单据（PI/装箱单/发票）

货主上传的贸易单据文件（PDF/图片/Excel），是 SI 字段抽取的输入源

doc_type string
单据类型（PI/装箱单/发票）
extraction_confidence number
OCR 抽取置信度
⚠️ 概念边界
≠ 贸易单据上的数据 ≠ 申报数据，须经 SI 校验与人工确认
参考对象
舱位（Space Slot）

特定航次可分配的舱位资源，含装载率/ETA 置信度/舱位保证状态，影响推荐排序

load_factor number
装载率
eta_confidence number
ETA 置信度
⚠️ 概念边界
≠ 舱位余量充足 ≠ 舱位保证一定兑现（旺季可能有甩柜风险）
参考对象
会员画像（Member Profile）

货主在 PlumSmart 体系的等级、交易记录与偏好，用于预填与复购推荐

tier enum
bronze / silver / gold / platinum
booking_history string
历史订舱记录
⚠️ 概念边界
≠ 新客无历史数据 ≠ 不能预填（以会话上下文+OCR 兜底）

情境 1
自然语言询价后的报价与舱位推荐
货主以自然语言询价，Agent 需识别意图、检索报价并按装载率/ETA/舱位保证综合推荐 Top3
📋 Required Evidence
E-Spot/E-Quote 报价引擎
确认即期/长时效报价的有效性与全包价构成
舱位评分服务
确认各航次装载率、ETA 置信度与舱位保证状态
会员画像（CRM）
确认货主等级与历史偏好，非新客时用于推荐
✅ Valid Actions
识别询价要素并检索匹配报价
按装载率/ETA/舱位保证综合排序生成 Top3 推荐
附可解释推荐理由供货主决策
❌ Invalid Actions
用 LLM 直接计算或伪造报价与评分
原因：报价与评分为事实数据，LLM 计算会产生幻觉，导致错误承诺
新客无历史数据时给出空预填或虚构推荐
原因：无证据支撑，会误导货主决策并造成信任受损
⚠️ Exception Triggers
当：报价引擎超时或无可用航次
→ 自动重试 1 次后降级提示，并建议邻近航线（Nearby Route Suggestions）
当：意图识别歧义（多航次/多箱型）
→ 对话追问澄清要素后再检索，避免错误报价
情境 2
一键订舱确认与提交
货主确认 Agent 预填的订舱表单，需经规则校验后提交订舱请求并签发确认书
📋 Required Evidence
订舱规则引擎（>200 条）
费率/信用/航线可用性校验全部通过，无拦截项
预填表单
货方/收货方/港口对/箱型/品名等必填字段齐全
✅ Valid Actions
基于会话上下文+画像自动预填订舱表单
运行订舱规则校验并标识异常字段
对外放行提交订舱请求并签发 Booking Confirmation
❌ Invalid Actions
校验未通过时静默提交订舱请求
原因：跳过校验会提交错误/风险订舱，产生后续单证与费用纠纷
未经货主确认直接签发确认书
原因：订舱为对外承诺动作，必须有货主人工放行（gate）
⚠️ Exception Triggers
当：信用受限/费率冲突/航线不可用
→ 标注原因提示补正，复杂单升级人工终审
当：新客无历史交易数据
→ 以会话上下文+PI/装箱单 OCR 预填兜底，并标注置信度
情境 3
SI 单证预填与推送
操作员上传贸易单据，Agent 抽取 SI 字段、规范品名/映射 HS 并做单证校验后推送单证系统
📋 Required Evidence
贸易单据（PI/装箱单/发票）
OCR 抽取品名/唛头/件数/毛重/体积/HS，标注置信度
智慧单证规则（>300 条）
单证校验全部通过，VGM/毛重差异等异常项已标识
✅ Valid Actions
OCR 抽取 SI 字段并标记低置信度字段
规范多语言品名并映射 HS 编码
校验通过后推送 SI 至单证系统
❌ Invalid Actions
带缺件（VGM 缺失/毛重超限）直接推送 SI
原因：缺件会导致退单返工，拉长订舱周期
HS 编码无法映射时擅自猜测编码
原因：错误 HS 编码会导致清关申报错误与合规风险
⚠️ Exception Triggers
当：OCR 抽取置信度低（模糊/破损单据）
→ 标黄待人工复核字段，不阻塞其余字段
当：VGM 缺失/毛重与装箱单差异超限
→ 生成补全项并提供填写示例，提示操作员一次补全
情境 4
出运跟踪与售后复购
货主对话查询运输状态，Agent 播报里程碑、预测 ETA 延误并提供 D&D 解读与复购推荐
📋 Required Evidence
控制塔/OMS 里程碑
确认开船/中转/最近已知 ETA 等最新里程碑
D&D 规则引擎
确认目的地免箱期与滞箱费规则（各港政策不同）
✅ Valid Actions
拉取里程碑并对话式播报，异常节点高亮
基于码头拥堵指数预测 ETA 延误并事前预警
解读免箱期并基于会员画像推荐复购与舱位预留

在 ETA 预测置信度低时发布确定性延误结论
原因：低置信度预测可能误报，会引发货主不必要的改配决策

原因：各港规则不同，直接下结论会导致费用争议

当：复杂投诉/情绪激动
→ 附完整上下文摘要升级人工，避免重复收集信息

# 业务本体：智能订舱Agent-本体设计
领域：集装箱电商订舱
Agent 角色：智能订舱执行助手（Booking Agent）
场景：SME 货主通过对话式智能订舱 Agent 完成询价、舱位推荐、订舱确认、单证预填与出运跟踪的端到端场景

## 1. 核心业务对象与概念边界
### 订舱请求（Booking Request） [核心对象]
- 定义：货主经确认后向系统提交的订舱意向，是订舱链路的触发对象，不等于已获舱位
- 属性定义：
  * status (enum)（可选值：draft / validated / submitted / confirmed / voided） - 订舱请求状态
  * container_type (string) - 箱型（如 40HQ）
  * port_pair (string) - 起运港-目的港港口对
- 关键概念边界（不可混淆）：
  ⚠️ 订舱请求已提交 ≠ 已签发 Booking Confirmation（可能被校验驳回）
  ⚠️ 订舱请求的状态不等于舱位状态，须以 Booking Confirmation 为准
### 订舱确认书（Booking Confirmation） [核心对象]
- 定义：确认已分配舱位并对外承诺的正式文件，含 Booking 编号与舱位保证，是后续单证与跟踪的锚点
- 属性定义：
  * booking_no (string) - 订舱编号（如 BK-2026-0901-001）
  * space_guaranteed (boolean) - 是否含舱位保证（Space Protection / Delay in Transit）
  * confirmed_at (datetime) - 签发时间
- 关键概念边界（不可混淆）：
  ⚠️ Booking Confirmation 是最快 1 分钟能签发的确定性文件，与报价单（Query）不同
  ⚠️ 舱位保证承诺 ≠ 实际已装载，违约时触发赔付流程
### 报价单（Quotation） [参考对象]
- 定义：报价引擎生成的 E-Spot/E-Quote 报价，含全包价构成与有效期，可锁定（Secured）
- 属性定义：
  * quote_type (enum)（可选值：e_spot / e_quote / secured_e_quote） - 报价类型
  * all_in_price (number) - 全包运价（USD）
  * validity (datetime) - 有效期
- 关键概念边界（不可混淆）：
  ⚠️ 报价单只是价格意向，不等于已锁定舱位或已订舱
  ⚠️ Secured E-Quote 锁价 ≠ 已签发订舱确认
### 装运指示（SI） [核心对象]
- 定义：货主提交的装运指示单证，含品名/唛头/件数/毛重/体积/HS 编码，是提单签发的依据
- 属性定义：
  * status (enum)（可选值：draft / extracted / validated / submitted） - SI 状态
  * hs_code (string) - HS 编码
  * vgm (number) - VGM 核实的集装箱总重
- 关键概念边界（不可混淆）：
  ⚠️ OCR 抽取的 SI 字段 ≠ 已通过规则校验（可能有 VGM 缺件）
  ⚠️ SI 校验通过 ≠ 已签发提单，需再进入提单流程
### 贸易单据（PI/装箱单/发票） [参考对象]
- 定义：货主上传的贸易单据文件（PDF/图片/Excel），是 SI 字段抽取的输入源
- 属性定义：
  * doc_type (string) - 单据类型（PI/装箱单/发票）
  * extraction_confidence (number) - OCR 抽取置信度
- 关键概念边界（不可混淆）：
  ⚠️ 贸易单据上的数据 ≠ 申报数据，须经 SI 校验与人工确认
### 舱位（Space Slot） [参考对象]
- 定义：特定航次可分配的舱位资源，含装载率/ETA 置信度/舱位保证状态，影响推荐排序
- 属性定义：
  * load_factor (number) - 装载率
  * eta_confidence (number) - ETA 置信度
- 关键概念边界（不可混淆）：
  ⚠️ 舱位余量充足 ≠ 舱位保证一定兑现（旺季可能有甩柜风险）
### 会员画像（Member Profile） [参考对象]
- 定义：货主在 PlumSmart 体系的等级、交易记录与偏好，用于预填与复购推荐
- 属性定义：
  * tier (enum)（可选值：bronze / silver / gold / platinum） - 会员等级
  * booking_history (string) - 历史订舱记录
- 关键概念边界（不可混淆）：
  ⚠️ 新客无历史数据 ≠ 不能预填（以会话上下文+OCR 兜底）

## 2. 对象关系依赖（Relationships）

  说明：一份订舱确认书对应装运指示（SI）单证
- 【贸易单据（PI/装箱单/发票）】 --(证明, 基数 N:1)--> 【装运指示（SI）】
  说明：多份贸易单据抽取生成一份 SI 字段
- 【舱位（Space Slot）】 --(约束, 基数 N:N)--> 【订舱确认书（Booking Confirmation）】
  说明：舱位分配结果约束订舱确认的签发与舱位保证兑现

  说明：会员画像覆盖预填字段（新客无数据时以会话兜底）

## 3. 行动边界限制（情境 - 证据 - 合法/禁止动作）
### 情境：自然语言询价后的报价与舱位推荐
描述：货主以自然语言询价，Agent 需识别意图、检索报价并按装载率/ETA/舱位保证综合推荐 Top3
必须核实的证据：
  - [E-Spot/E-Quote 报价引擎] 确认即期/长时效报价的有效性与全包价构成
  - [舱位评分服务] 确认各航次装载率、ETA 置信度与舱位保证状态
  - [会员画像（CRM）] 确认货主等级与历史偏好，非新客时用于推荐
✅ 合法动作（允许执行）：
  - 识别询价要素并检索匹配报价
  - 按装载率/ETA/舱位保证综合排序生成 Top3 推荐
  - 附可解释推荐理由供货主决策
❌ 禁止动作（严禁执行，防范错误假设）：
  - 用 LLM 直接计算或伪造报价与评分 （禁止原因：报价与评分为事实数据，LLM 计算会产生幻觉，导致错误承诺）
  - 新客无历史数据时给出空预填或虚构推荐 （禁止原因：无证据支撑，会误导货主决策并造成信任受损）
⚠️ 异常触发规则：
  - 当满足条件【报价引擎超时或无可用航次】 → 必须执行：自动重试 1 次后降级提示，并建议邻近航线（Nearby Route Suggestions）
  - 当满足条件【意图识别歧义（多航次/多箱型）】 → 必须执行：对话追问澄清要素后再检索，避免错误报价
### 情境：一键订舱确认与提交
描述：货主确认 Agent 预填的订舱表单，需经规则校验后提交订舱请求并签发确认书
必须核实的证据：
  - [订舱规则引擎（>200 条）] 费率/信用/航线可用性校验全部通过，无拦截项
  - [预填表单] 货方/收货方/港口对/箱型/品名等必填字段齐全
✅ 合法动作（允许执行）：
  - 基于会话上下文+画像自动预填订舱表单
  - 运行订舱规则校验并标识异常字段
  - 对外放行提交订舱请求并签发 Booking Confirmation
❌ 禁止动作（严禁执行，防范错误假设）：
  - 校验未通过时静默提交订舱请求 （禁止原因：跳过校验会提交错误/风险订舱，产生后续单证与费用纠纷）
  - 未经货主确认直接签发确认书 （禁止原因：订舱为对外承诺动作，必须有货主人工放行（gate））
⚠️ 异常触发规则：
  - 当满足条件【信用受限/费率冲突/航线不可用】 → 必须执行：标注原因提示补正，复杂单升级人工终审
  - 当满足条件【新客无历史交易数据】 → 必须执行：以会话上下文+PI/装箱单 OCR 预填兜底，并标注置信度
### 情境：SI 单证预填与推送
描述：操作员上传贸易单据，Agent 抽取 SI 字段、规范品名/映射 HS 并做单证校验后推送单证系统
必须核实的证据：
  - [贸易单据（PI/装箱单/发票）] OCR 抽取品名/唛头/件数/毛重/体积/HS，标注置信度
  - [智慧单证规则（>300 条）] 单证校验全部通过，VGM/毛重差异等异常项已标识
✅ 合法动作（允许执行）：
  - OCR 抽取 SI 字段并标记低置信度字段
  - 规范多语言品名并映射 HS 编码
  - 校验通过后推送 SI 至单证系统
❌ 禁止动作（严禁执行，防范错误假设）：
  - 带缺件（VGM 缺失/毛重超限）直接推送 SI （禁止原因：缺件会导致退单返工，拉长订舱周期）
  - HS 编码无法映射时擅自猜测编码 （禁止原因：错误 HS 编码会导致清关申报错误与合规风险）
⚠️ 异常触发规则：
  - 当满足条件【OCR 抽取置信度低（模糊/破损单据）】 → 必须执行：标黄待人工复核字段，不阻塞其余字段
  - 当满足条件【VGM 缺失/毛重与装箱单差异超限】 → 必须执行：生成补全项并提供填写示例，提示操作员一次补全
### 情境：出运跟踪与售后复购
描述：货主对话查询运输状态，Agent 播报里程碑、预测 ETA 延误并提供 D&D 解读与复购推荐
必须核实的证据：
  - [控制塔/OMS 里程碑] 确认开船/中转/最近已知 ETA 等最新里程碑
  - [D&D 规则引擎] 确认目的地免箱期与滞箱费规则（各港政策不同）
✅ 合法动作（允许执行）：
  - 拉取里程碑并对话式播报，异常节点高亮
  - 基于码头拥堵指数预测 ETA 延误并事前预警
  - 解读免箱期并基于会员画像推荐复购与舱位预留
❌ 禁止动作（严禁执行，防范错误假设）：
  - 在 ETA 预测置信度低时发布确定性延误结论 （禁止原因：低置信度预测可能误报，会引发货主不必要的改配决策）
  - 忽略各港免箱期政策差异，直接适用单一 D&D 结论 （禁止原因：各港规则不同，直接下结论会导致费用争议）
⚠️ 异常触发规则：
  - 当满足条件【高风险延误（甩柜/改船）】 → 必须执行：升级人工按 Delay in Transit 条款生成改配方案与赔付预判
  - 当满足条件【复杂投诉/情绪激动】 → 必须执行：附完整上下文摘要升级人工，避免重复收集信息

## 4. 状态流转与全局护栏（Workstreams & States）
### 执行流（Workstream）：订舱执行
描述：从报价确认到签发 Booking Confirmation 的完整执行流
锚点对象：报价单（Quotation）、订舱请求（Booking Request）、订舱确认书（Booking Confirmation）
状态节点及迁移路径：
  - 状态：报价中 (bk_quoting)
    状态定义：货主询价，Agent 检索报价并推荐，尚在方案选择阶段
    可用的状态转移路径：
      * --[货主确认选定方案] (核实证据: 货主对推荐 Top3 作出选定（含锁价/即期取舍）)--> 到达状态 已选方案 (性质: 正常迁移)
      * --[货主放弃或转其他平台] (核实证据: 对话中止或明确放弃意图)--> 到达状态 报价流失 (性质: 异常分支)
  - 状态：已选方案 (bk_selected)
    状态定义：货主已选定报价方案，待预填与校验
    可用的状态转移路径：
      * --[自动预填并运行订舱规则校验] (核实证据: 预填字段齐全且校验通过（费率/信用/航线）)--> 到达状态 校验通过待确认 (性质: 正常迁移)
      * --[校验发现拦截项] (核实证据: 校验规则返回信用受限/费率冲突/航线不可用)--> 到达状态 校验被拒 (性质: 异常分支)
  - 状态：校验通过待确认 (bk_validated)
    状态定义：表单校验通过，等待货主人工放行
    可用的状态转移路径：
      * --[货主对外放行确认提交] (核实证据: 货主确认提交订舱请求（gate 人工放行）)--> 到达状态 已订舱 (性质: 正常迁移)
  - 状态：已订舱 (bk_confirmed)
    状态定义：订舱请求提交成功并签发 Booking Confirmation
  - 状态：校验被拒 (bk_rejected)
    状态定义：校验未通过，需补正或升级人工终审
    可用的状态转移路径：
      * --[补正资料后重新校验] (核实证据: 补正字段通过再次校验)--> 到达状态 校验通过待确认 (性质: 异常恢复)
  - 状态：报价流失 (bk_lost)
    状态定义：货主放弃本方案或流失
🔒 全局不可绕过护栏规则：
  - 报价与评分必须来自确定性服务，LLM 不直接产出价格或得分
  - 订舱为对外承诺动作，必须货主人工放行（gate）后方可提交
  - 新客无历史数据时以会话上下文+OCR 预填兜底，禁止空预填或虚构推荐
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【单证处理】 满足条件【状态到达 bk_confirmed（已签发 Booking Confirmation）】，则受到影响：触发单证处理执行流，可开始 SI 预填
### 执行流（Workstream）：单证处理
描述：从上传贸易单据到 SI 校验通过并推送单证系统的执行流
锚点对象：贸易单据（PI/装箱单/发票）、装运指示（SI）、订舱确认书（Booking Confirmation）
状态节点及迁移路径：
  - 状态：单据已上传 (sd_uploaded)
    状态定义：操作员上传 PI/装箱单/发票，待 OCR 抽取
    可用的状态转移路径：
      * --[OCR 抽取 SI 字段] (核实证据: 抽取品名/件数/毛重/体积/HS 且标记置信度)--> 到达状态 字段已抽取 (性质: 正常迁移)
  - 状态：字段已抽取 (sd_extracted)
    状态定义：SI 字段已抽取，待规范品名/HS 映射与校验
    可用的状态转移路径：
      * --[品名规范+HS 映射+单证校验] (核实证据: 校验通过，VGM/毛重差异等异常项已标识)--> 到达状态 校验通过 (性质: 正常迁移)
      * --[校验发现缺件/异常] (核实证据: VGM 缺失或毛重差异超限或 HS 无法映射)--> 到达状态 补件处理中 (性质: 异常分支)
  - 状态：校验通过 (sd_validated)
    状态定义：SI 校验通过，可推送单证系统
    可用的状态转移路径：
      * --[推送 SI 至单证系统] (核实证据: 单证系统接收成功)--> 到达状态 已提交 (性质: 正常迁移)
  - 状态：补件处理中 (sd_exception)
    状态定义：存在缺件/异常，Agent 给示例待操作员一次补全
    可用的状态转移路径：
      * --[操作员一次补全并复检] (核实证据: 补全字段通过复检校验)--> 到达状态 校验通过 (性质: 异常恢复)
  - 状态：已提交 (sd_submitted)
    状态定义：SI 已推送单证系统，进入提单流程
🔒 全局不可绕过护栏规则：
  - SI 校验不通过必须提示异常项并给示例，禁止带缺件推送单证系统
  - HS 编码无法映射时禁止擅自猜测，必须提示人工复核
  - OCR 低置信度字段须标黄待复核，不得静默按抽取值推送
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【订舱执行】 满足条件【单证流程依赖订舱确认书已签发（bk_confirmed）】，则受到影响：无订舱确认书时单证流程不能启动，避免孤立单证
### 执行流（Workstream）：出运跟踪与售后
描述：从出运里程碑播报到 ETA 延误预警、售后与复购推荐的执行流
锚点对象：订舱确认书（Booking Confirmation）、舱位（Space Slot）、会员画像（Member Profile）
状态节点及迁移路径：
  - 状态：跟踪中 (tr_tracking)
    状态定义：货主查询运输状态，Agent 拉取里程碑并播报
    可用的状态转移路径：
      * --[ETA 预测高风险延误] (核实证据: ETA 预测模型输出高延误概率（如 68%）)--> 到达状态 延误预警中 (性质: 异常分支)
      * --[运输完成进入售后] (核实证据: 货主转售后咨询或到达目的地)--> 到达状态 售后复购 (性质: 正常迁移)
  - 状态：延误预警中 (tr_warned)
    状态定义：高风险延误，Agent 事前预警，必要时升级人工改配
    可用的状态转移路径：
      * --[延误解除或已改配，恢复正常跟踪] (核实证据: 新 ETA 确认或改配落地，延误风险解除)--> 到达状态 跟踪中 (性质: 异常恢复)
  - 状态：售后复购 (tr_after_sales)
    状态定义：货主咨询 D&D/权益，Agent 解读并推荐复购、复杂问题转人工
🔒 全局不可绕过护栏规则：
  - ETA 预测置信度低时降级为事后通知，不作为改配依据
  - 延误处置/改配赔付属对外承诺，必须人工终审放行
  - D&D/免箱期规则各港不同，口径不一致时标注待人工确认，禁止直接下结论
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【订舱执行】 满足条件【跟踪对象依赖订舱确认书编号（bk_confirmed）】，则受到影响：无有效订舱编号时无法建立跟踪上下文

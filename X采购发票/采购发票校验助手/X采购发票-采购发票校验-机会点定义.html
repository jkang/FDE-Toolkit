1. 多源发票智能归集（消除系统孤岛）
重复性替代 根因：数据分散在乐企/供应商上传/采购补录多源，靠人工下载归集、易漏票重票 能力：Agent / 多源适配器 / 去重查漏
1
① 机会点一句话描述
为应付会计构建「多源发票智能归集」，把「人工在乐企、供应商上传区、采购补录之间逐张下载归集」升级为「一键触发 + 多源自动同步 + 查重查漏」，让本批发票全部入池且不漏不重。
2
② 业务角色及场景
角色：应付会计（发起与补录）、采购业务员（补录 PO 关联）。 场景：应付会计每天/每批发起归集，系统从乐企平台（IF001）、供应商上传区、采购补录多渠道拉取发票，按发票号去重并核验归集完整性。
3
③ 问题痛点
发票来源分散（电子税务局/乐企、供应商平台、纸质补录），人工逐张下载归集耗时且易漏票重票，系统孤岛在采集端最先暴露。
4
④ 方案假设
用多源适配器定时/手工拉取 → 按发票号与关键字段查重 → 完整性校验并标记重复/缺失 → 归集看板按渠道分栏展示；无 API 的渠道（如纸质补录）保留人工登记入口 → 把归集覆盖率推向 100%。
5
⑤ 价值收益
归集从人工逐张走向一键多源同步；漏票/重票下降；归集覆盖率 100%。

2. 票面识别与真伪/抬头校验
重复性替代 根因：票面字段靠人工读取，版式差异/模糊票易错，真伪与抬头校验靠人工 能力：多模态 OCR / 版面理解 / 字典校验
1
① 机会点一句话描述
为应付会计构建「票面识别与真伪/抬头校验」，把「人工读取发票号/金额/税额/税号并逐张验真校抬头」升级为「AI 结构化识别 + 置信度门禁 + 自动校验」，低置信自动转人工复核。
2
② 业务角色及场景
角色：应付会计（复核低置信字段）、采购业务员（仅自有权限 PO 复核）。 场景：发票入池后，AI 识别 5 个关键字段与行项目，按供应商/税号字典校验真伪与购方抬头，置信度 <95% 标红转人工。
3
③ 问题痛点
票面版式多样、存在模糊票与新版式，人工读取易错；真伪/抬头校验依赖逐张核对，效率低。
4
④ 方案假设
多模态模型识别字段 + 版面定位 → 置信度门禁（<95% 转人工复核）→ 调用供应商/税号/科目字典校验真伪与抬头 → 结构化结果回写并标注票面位置供追溯 → 把识别准确率推向 >95%。
5
⑤ 价值收益
票面识别从人工读取走向 AI 结构化；识别准确率 >95%；真伪/抬头校验覆盖率 100%。

3. 三单匹配与数量扣减自动化
流程创新 根因：人工逐票逐行比对发票/入库送货/PO，高耗时且高频错误 能力：规则引擎 / Agent 编排 / 行级匹配
1
① 机会点一句话描述
为应付会计构建「三单匹配与数量扣减自动化」，把「人工逐票逐行比对发票、入库/送货、PO」升级为「以发票行为主线行级匹配 + 数量扣减 + 差异标注」，人工只处理差异。
2
② 业务角色及场景
角色：应付会计（确认匹配结果）。 场景：以发票行为主线汇入 PO 行/入库行/送货行，执行三层匹配（发票行↔送货/入库行、入库单↔PO 行、发票行↔PO 行）与数量扣减（发票数量扣减入库/送货数量），标注差异。
3
③ 问题痛点
三单匹配人工逐票逐行比对，单票耗时高、错误率不低；口径复杂（三层匹配、一对多/多对多、数量扣减）靠人脑维持。
4
④ 方案假设
规则引擎承载三层匹配结构与数量扣减口径 → 行级自动匹配并生成匹配关系表（不覆盖原始单据）→ 差异高亮 + 四数量对照报表 → 差异转异常确认 → 把匹配错误率压到目标值。
5
⑤ 价值收益
三单匹配从人工逐票走向行级自动匹配；单票校验耗时降至秒级；匹配错误率下降、杜绝静默错配。

4. 差异容忍与异常判定知识化
高认知辅助 根因：差异容忍与异常判定依赖资深经验、无书面标准，换人即断档 能力：知识沉淀 / 规则引擎 / LLM 归因
1
① 机会点一句话描述
为应付会计构建「差异容忍与异常判定知识化」，把「资深会计凭经验判断哪些差异可容忍、哪些必拉人」升级为「规则化差异容忍判定 + 异常类型标注 + 处理建议与升级路径」，让经验可复核可传承。
2
② 业务角色及场景
角色：应付会计（复核判定）、采购业务员（异常确认与沟通）、财务负责人（升级裁决）。 场景：三单匹配出现数量/金额差异时，按差异容忍规则判定可容忍或必拉人，并生成异常类型（补单/换票/冲红/退票/抬头税号不符/单价不符/数量超差/金额超尾差/跨期发票）与处理建议。
3
③ 问题痛点
差异容忍阈值与异常类型清单无书面标准，集中在少数资深人员；异常沟通与升级路径靠口传，人员流动即断层。
4
④ 方案假设
把差异容忍规则（数量无容忍区间、金额尾差 ≤1 元且 ≤0.5% 自动容忍——领域专家假设值待访谈回填）落成规则引擎 → LLM 生成异常类型归因与处理建议 → 输出沟通对象与升级路径 → 容忍内自动放行、超容忍必拉人 → 把隐性经验转为可复核的标准动作。
5
⑤ 价值收益
异常判定从依赖经验走向规则化 + 建议化；异常处理周期缩短；经验可复核可传承。

覆盖范围⑥ 影响范围全部异常发票；受益角色：应付会计 + 采购业务员 + 财务负责人
发生频度⑤ 发生频度每张差异发票一次判定
单次收益⑦ 每次发生对业务的影响凭经验判断 → 规则判定 + 建议；判定一致性提升、沟通往返减少
累计影响⑧ 累计对业务影响异常处理周期缩短；经验断层风险下降
5. 预制过账与台账归档自动化
重复性替代 根因：预制/过账/台账/归档全靠人工，耗时且易错，硬门禁靠人工记忆 能力：规则引擎 / 跨系统编排 / 硬门禁校验
1
① 机会点一句话描述
为应付会计与财务负责人构建「预制过账与台账归档自动化」，把「人工逐票预制、过账审核、更新台账、打印归档、回写乐企状态」升级为「硬门禁前置校验 + 批量预制过账 + 台账归档状态全链路自动更新」。
2
② 业务角色及场景
角色：应付会计（批量预制）、财务负责人（过账审核）、系统（乐企状态回写）。 场景：匹配通过的票批量预制，预制/过账/乐企三类硬门禁前置条件全绿才放行；过账确认后凭证号、乐企入账标识、台账、归档索引一次到位。
3
③ 问题痛点
预制、过账、台账更新、打印归档、乐企状态回写全靠人工，耗时且易错；三类硬门禁前置条件靠人工记忆，遗漏导致返工。
4
④ 方案假设
用硬门禁规则校验预制（已识别/匹配关系/差异说明/信息完整/校验通过/权限）、过账（已预制/预制有效/财务权限）、乐企（已过账/有凭证号/权限）三类前置 → 批量预制过账 → 自动回写凭证号、乐企状态、台账、归档索引 → 把入账自动化覆盖率推向 100%。
5
⑤ 价值收益
预制过账归档从人工逐票走向批量自动；入账自动化覆盖率 100%；硬门禁遗漏导致的返工下降。

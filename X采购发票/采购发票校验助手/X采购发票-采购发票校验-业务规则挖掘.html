三单匹配口径与数量扣减规则 使用点 · 以发票行为主线汇入三单行信息使用点 · 行级核对数量并扣减使用点 · 返回三单匹配重跑
①决策因子
匹配主线（发票行）：以发票行为主线、非整张发票为唯一粒度，汇入 PO 行/入库行/送货单行 (来源 客户开发方案设计文档)
匹配关系基数：支持一对一/一对多/多对多（一张发票可对多个 PO 行/入库单/送货单） (来源 客户开发方案设计文档)
三层匹配结构：第一层发票行↔送货/入库行；第二层入库单↔PO 行；第三层发票行↔PO 行 (来源 客户开发方案设计文档)
数量差异：以发票数量扣减入库/送货数量后的差异（不校验入库单与送货单一致性） (来源 采购发票、入库单、送货单)
匹配关系表：记录发票行↔送货单行↔入库单行↔PO 行对应关系与差异，不覆盖原始单据数据 (来源 客户开发方案设计文档)
→
②逻辑分支
发票数量 = 入库/送货数量（扣减后恰为 0） → → 标记数量一致，进入金额核对
发票数量 < 入库/送货数量（部分入库/多送） → → 标记为正常（部分入库），不判超差
发票数量 > 入库/送货数量 → → 标记数量超差，必拉人（数量无容忍区间）
6 条匹配规则（供应商/行金额/总金额/数量/物料/PO 完整性）任一不一致 → → 逐行标记差异，记入匹配关系表
→
③分支动作
以发票行为主线执行三层匹配与 6 条匹配规则，按发票数量扣减入库/送货数量，行级差异记入匹配关系表、不覆盖原始单据。
→
④冲突仲裁
以发票行为主线；差异记录到匹配关系表、不覆盖原始单据；四数量对照报表（PO/送货/入库/发票）仅供人工定位差异来源，最终以 ERP 接口返回为准。
例外/HITL：数量超差 → 匹配差异确认点拉人；入库单冲销/送货单缺失 → 人工介入。
金额比对规则 使用点 · 行级核对金额与差异
①决策因子
发票金额：发票票面不含税金额（比对基准） (来源 采购发票)
合同/PO 金额：合同或采购订单约定金额 (来源 采购订单（PO）)
差异类型：金额>合同、数量不符、单价不符 (来源 采购发票、采购订单（PO）)
→
②逻辑分支
发票金额 ≤ 合同/PO 金额（经 ERP 模拟校验接口判定） → → 标记金额匹配通过
发票金额 > 合同/PO 金额 → → 标记金额差异，进入异常判定
→
③分支动作
以不含税金额为基准、经 ERP 模拟校验接口判定发票金额是否超过合同/PO 金额；本平台仅感知结果、不落规则。
→
④冲突仲裁
金额比对规则由 ERP 模拟发票校验接口承载、本平台不落规则，仅感知接口返回的通过/差异结果，保证 ERP 规则调整后本平台无需调整；以不含税金额为基准。
例外/HITL：接口返回差异 → 匹配差异确认点拉人；「等于边界」归属待访谈确认后锁定。
差异容忍与异常判定经验 使用点 · 判定行级匹配结果并记录匹配关系使用点 · 判定异常类型并生成处理建议
①决策因子
数量差异：发票与入库/送货的数量差 (来源 采购发票、入库单、送货单)
金额尾差：金额比对的小额差异（差异金额与差异率） (来源 采购发票、采购订单（PO）)
异常类型：补单/换票/冲红/退票/抬头税号不符/单价不符/数量超差/金额超尾差/跨期发票 (来源 采购发票、归档文件)
→
②逻辑分支
数量差异 = 0 且 金额尾差 ≤ 1 元 且 ≤ 0.5% → → 标记可容忍，自动放行进入预制
数量超差（发票数量 > 入库/送货数量，无容忍区间） → → 必拉人，标记数量超差
金额尾差 > 1 元 或 > 0.5% → → 必拉人，标记金额超尾差
任一超容忍（数量 OR 金额） → → 必拉人（两者为独立风险，任一超容忍即拉人）
→
③分支动作
判定差异是否可容忍：数量无容忍区间、金额尾差 ≤1 元且 ≤0.5% 自动容忍，任一超容忍必拉人；默认路径指向人工确认（安全行为）。
→
④冲突仲裁
因子优先级：先看数量超差 → 再看金额尾差 → 再看供应商历史异常记录；数量超差 OR 金额超尾差 → 必拉人（独立风险，不叠加、不互相抵消）；阈值与异常类型清单为领域专家假设值，待访谈回填。
例外/HITL：容忍内自动通过；超容忍 100% 拉人（匹配差异确认点/异常升级确认点）；兜底升级：应付会计 → 仍无法裁决 → 财务负责人。
预制/过账/乐企前置硬门禁规则 使用点 · 预制发票凭证使用点 · 过账生成会计凭证使用点 · 更新电子税务局发票状态
①决策因子
预制前置：发票已识别；发票行已存在匹配关系；关键差异已保存说明；供应商/PO/入库信息完整；金额/数量/物料校验通过或已备注；用户具备预制权限 (来源 客户开发方案设计文档)
过账前置：发票已预制；ERP 预制状态有效；用户具备财务过账权限 (来源 客户开发方案设计文档)
乐企前置：发票已过账；存在 ERP 凭证号；用户具备乐企状态更新权限 (来源 客户开发方案设计文档)
→
②逻辑分支
预制前置全部满足 → → 提交 ERP 预制发票（IF005）
预制前置任一不满足（如成本中心缺失） → → 拦截并给出失败原因与降级建议（补齐后重试）
过账前置满足且财务负责人已确认 → → 调用 ERP 过账（IF006）生成凭证并回写凭证号
乐企前置满足 → → 回写乐企入账标识（IF002）；过渡期提示财务人工勾选并记录
→
③分支动作
预制、过账、乐企更新三类动作的硬门禁前置校验：满足才执行，不满足即拦截并给降级建议，过账前必停财务负责人确认。
→
④冲突仲裁
预制/过账/乐企三类硬门禁为强前置，任一不满足即阻断、不得越级执行；过账前必停人工确认（财务负责人），不可自动放行。
例外/HITL：前置未满足 → 标红拦截 + 降级建议；接口失败重试无果 → 转人工线下处理并入待补队列。

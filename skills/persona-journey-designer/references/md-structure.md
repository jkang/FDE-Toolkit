## 字段说明

| 字段 | 要求 |
|---|---|
| 画像类型 | `主用户` / `次要用户` |
| 主用端末 | `PC（案头）` / `移动（现场）` / 两者 |
| 旅程工作情境 | 一句话命名（如「复盘与情报任务下发」） |
| 端末 | `PC · 案头` / `移动 · 现场`（**必须标**） |
| 参与角色 | `主责 + 参与 / 知会`（**允许跨角色**） |
| 端到端目标 | 从…到…（一句） |
| Job Story | 固定句式：当…我想要…以便… |
| 起点 / 终点 | 目标触发 / 目标完成，各一句 |
| 旅程表 | 5–7 行；列固定为 `# 阶段 角色 用户动作 触点 期望结果` |
| 产品介入点 | 一句，标明产品在旅程的哪几步帮忙 |
| 衔接 | 承接哪条旅程、产出流向哪条旅程 |
| 矩阵图例 | ● 主责 · ○ 参与 / 知会 · — 不适用 |
| 覆盖校验 | 分「画像」与「端末」两张小表 |

---

## 硬性约束

1. **旅程按工作情境（端末）划分**：PC 案头与移动现场**必须分开**；同一情境 + 同一端到端目标的连续步骤**合并**为一条。
2. 画像数量 2–5 类；必须区分主用户 / 次要用户。
3. 每条旅程 5–7 步；**允许跨角色**（写清主责与参与）。
4. 每条旅程必须写清**起点（目标触发）**与**终点（目标完成）**，以及**衔接**。
5. 每条旅程必须有「**产品介入点**」。
6. 旅程表**不得**出现 UI / 字段 / AI 交互细节列。
7. 必须有「画像 × 旅程矩阵」与「角色与端末覆盖校验」两段。
8. 一线执行角色必须出现在画像清单中。

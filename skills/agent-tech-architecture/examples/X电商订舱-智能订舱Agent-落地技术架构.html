3 条链共享读写本体 / 按需调用 MCP
共享底座
🧱 本体（确定性底座）

读 R：会员画像（报价推荐）、订舱单 / 规则（表单预填）。
写 W：订舱请求 / 确认书（提交签发）、SI（推送入库）。
对象 / 关系 / 状态迁移 + 业务事实；Skill 读写本体，不靠 LLM 猜事实。

🔌 MCP / 外部系统

调用点：报价引擎（报价检索）、OMS（提交订舱）、智慧单证系统（推送 SI）、控制塔 / CRM（里程碑 / 画像）、支付网关（支付核销）。
仅需要外部读写的步骤才走 MCP。

📚 知识库 / RAG

检索点：品名词典 / HS 库、D&D 规则库。
规则校验走规则引擎而非向量检索；法规 / SOP 等非结构化知识走 RAG。

🩷 异常池（人工终审）：校验不通过 / 信用受限 / HS 无法映射 / 复杂投诉 / Loop 超限 → 升级人工，附上下文摘要。

失败 / 降级 / 兜底

触发处理类型
报价引擎超时 / 无可用航次重试 1 次 → 降级提示 + 邻近航线建议retry / fallback
意图识别歧义（多航次 / 多箱型）对话追问澄清要素后再检索fallback
表单校验不通过（信用受限 / 费率冲突）标注原因提示补正 → 复杂单升级人工终审escalate
OCR 抽取置信度低（模糊 / 破损）标黄待人工复核字段，不阻塞其余字段fallback
OMS / 单证系统接口失败重试 2 次 → 标记同步异常并通知 ITretry / escalate
支付失败（汇率 / 通道异常）自动切换本地支付通道 → 仍失败转人工retry / fallback
ETA 预测置信度低降级为事后通知，不作为改配依据fallback
复杂问题 AI 无法解决附完整上下文摘要升级人工escalate

KPI 锚定（链路 → 指标）

在线订舱确认时效① 报价推荐 + ② 订舱执行　≤2h / 头部分钟级
AI 分流率① 报价推荐 + ③ 跟踪售后　30%+
SME 全流程自助率① + ②　向渗透率 40% 演进
单证一次提交通过率② 单证预填　往返补件 2~3 轮 → 1 轮
舱位保证兑现率③ 跟踪预警　95%+
复杂问题一次性解决率③ 售后　附摘要转人工

护栏落点

事实性计算（报价 / 评分 / 校验）走确定性服务 / 本体 / 规则引擎，LLM 不产出
写操作（订舱 / 支付 / SI 推送）必须人工放行，禁止静默通过
新客无历史数据会话 + OCR 兜底并标置信度，不准空预填
⚠️ 口径待确认（MCP）：本方案把「报价引擎 / OMS / 智慧单证 / 控制塔 / 支付网关」画成 MCP 外部调用；若场景确认「MCP=0，业务数据全部来自绑定本体」，则把这些归入本体 / 内部服务，并在底座标 N/A。二者需二选一后再定稿。

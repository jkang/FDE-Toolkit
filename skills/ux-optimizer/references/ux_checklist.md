# UX-Optimizer · 常见不专业 UX 问题检查清单（Checklist）

用于交付前逐项排查**最常见的"不够专业"UX 问题**，发现即修复。每一项都是 impeccable / frontend-design 体系下的公认反模式（Anti-pattern）。输出前应对照本清单逐项勾选，并实际检查 + 优化。

> 本清单独立于 design.md（咨询报告规范），专指**产品级 MVP-prototype** 的专业度缺陷。
> 覆盖维度：对比度 / 可访问性 / 排版层级 / 布局 / 组件状态 / 交互 / 动效 / 文案 / 响应式。

---

## 一、色彩与对比度（最容易翻车）

- [ ] **正文对比度**：正文文字与背景 ≥4.5:1；大号文字（≥18pt 或 ≥14pt 粗体）≥3:1。逐一对色对跑 `scripts/contrast_check.py`。
- [ ] **Placeholder 达标**：输入框 placeholder 文字 ≥4.5:1（浅灰 placeholder 常见失败）。
- [ ] **禁用低对比反模式**：无 `gold`/`cyan`/`processing` 深底深字；无浅灰字叠白底；无深灰底配深灰字；无灰字叠彩色底。
- [ ] **状态三重表达**：状态不只靠颜色（色盲/弱视不可读）——需「色 + 图标 + 文字」同时表达。
- [ ] **强调色克制**：强调色用量 5-10%，大面积用中性/品牌主色，避免"满屏品牌色"。
- [ ] **alpha 透明度使用**：避免大面积 rgba/hsla 叠色（对比度不可控）；仅焦点环/交互态允许。
- [ ] **无纯黑纯灰**：禁用 `#000` / 纯灰大面，用带品牌色相的近黑（如 `#10213E`）。
- [ ] **危险色对**：无红底绿字/绿底红字、蓝底红字、黄字白底。

## 二、可访问性（WCAG）

- [ ] **焦点可见**：所有可交互元素 `:focus-visible` 有 ≥3:1 高对比焦点环（2-3px，非 `outline:none` 了事）。
- [ ] **字体不锁死**：正文用 rem/em（非 px），浏览器可缩放；未禁用 `user-scalable=no`。
- [ ] **正文最小 16px**：移动端正文 ≥16px，避免小字压眼。
- [ ] **触摸目标**：可点元素热区 ≥44×44px（含图标按钮，用 ::before 扩展）。
- [ ] **键盘可达**：Tab 焦点顺序正确；组件组用 roving tabindex；有 skip link 跳导航。
- [ ] **对话框焦点**：用 `<dialog>`/`inert` 实现焦点陷阱，Escape 可关。
- [ ] **图片 alt**：有意义的图片有 `alt`；装饰图空 `alt`。
- [ ] **减少动效**：`@media (prefers-reduced-motion: reduce)` 生效（动效降级/关闭）。

## 三、排版与层级（字体层次）

- [ ] **字号过多**：无太多相近字号（14/15/16/18 堆叠）。用 5 级少字号+大对比体系。
- [ ] **标题/正文反差**：主标题比正文大 3:1 或更突出；无"标题与正文几乎同大"。
- [ ] **层级多维**：层级同时用「大小+字重+色彩+留白」2-3 维强化，非仅靠 size。
- [ ] **垂直节奏**：body `line-height` 为间距基准，纵向间距是行高的倍数。
- [ ] **数字对齐**：数据表格/指标用 `font-variant-numeric: tabular-nums`（等宽数字对齐）。
- [ ] **字距字重**：标题字距 `-0.02em`、字重 600；正文 400；全站字重层级统一。
- [ ] **字体不过多**：全项目 ≤2-3 个字体族；避免相似字体混搭造成张力。
- [ ] **正文行宽**：正文 max-width `65ch` 左右，勿过长过窄。

## 四、布局与空间

- [ ] **间距体系**：用 4pt 底（4/8/12/16/24/32/48/64/96）；无随意值（10/15 等离线）。
- [ ] **间距非全等**：兄弟间距用 `gap`，区块间大、组内小，有节奏非全程等距。
- [ ] **squint test（眯眼测试）**：眯眼仍能辨出最重要/次重要/分组——否则层级有问题。
- [ ] **卡片克制**：不嵌套卡片；卡片仅用于需要独立边界/对比/可交互的内容。
- [ ] **触摸目标 vs 视觉**：icon 按钮视觉小但热区够大。
- [ ] **网格自适应**：卡片网格用 `repeat(auto-fit, minmax(280px,1fr))` 无需断点。

## 五、组件状态（六态 / 八态）

- [ ] **状态完备**：default / hover / focus / active / disabled / loading / error / success 全设计。
- [ ] **hover≠focus**：键盘用户看不到 hover，两者都实现且不互相替代。
- [ ] **loading 用骨架屏**：优先 skeleton 而非纯 spinner，预测内容形状。
- [ ] **错误可恢复**：错误明确原因 + 下一步动作；非笼统 "Something went wrong"。
- [ ] **空态不裸**：空态给 icon + 说明 + 引导 CTA，非空白。
- [ ] **乐观更新**：低风险操作先展示成功再回滚；支付/删除等高风险不用。

## 六、表单与输入

- [ ] **label 可见**：用可见 `<label>`，不用 placeholder 当 label（输入即消失）。
- [ ] **校验时机**：blur 校验（非每键），密码强度除外。
- [ ] **错误位置**：错误在字段下方，用 `aria-describedby` 关联。
- [ ] **格式示例**：用 placeholder 给格式示例；非显而易见字段说明"为什么问"。

## 七、动效与微交互

- [ ] **时长**：反馈 100-300ms；状态切换 200-300ms；布局 300-500ms；入场 500-800ms；退出=入场 75%。
- [ ] **缓动**：用 ease-out-quart/quart/expo（`cubic-bezier(0.25,1,0.5,1)` 等），禁用默认 `ease` 和弹跳/弹性曲线。
- [ ] **只动 transform/opacity**：不动画 height/width 引发重排。
- [ ] **动效克制**：不做动画疲劳，不每处都动；不靠动画掩盖加载慢。
- [ ] **stagger 上限**：`animation-delay: calc(var(--i)*50ms)`，总时长 ≤500ms。

## 八、文案（UX Writing）

- [ ] **术语统一**：Delete/Remove/Trash → 统一 Delete；Sign in/Log in → 统一。
- [ ] **无冗词**：标题已说明则删简介；按钮清晰则不重复解释。
- [ ] **loading 文案具体**："正在保存草稿…" 而非 "Loading..."。
- [ ] **不怪用户**：不写 "You made an error"，改 "This field is required"。
- [ ] **确认框克制**：能用 undo 不用 confirm；确认框给具体按钮文案（Delete project / Keep project）。
- [ ] **面向翻译**：数字与文案分离、完整句子作单串、避免缩写。

## 九、响应式

- [ ] **断点齐全**：375 / 768 / 1024 / 1440 生效，内容不溢出、不挤压。
- [ ] **表格→卡片**：小屏表格转卡片（`display:block` + `data-label`）。
- [ ] **移动优先**：非 desktop-first；不设备检测，用特性检测。
- [ ] **真实设备**：至少在真实手机/平板上验证，不只 DevTools 模拟。

## 十、注入与验证（工程）

- [ ] `tokens.js` 已注入（色彩/字体/间距/圆角/阴影 token）
- [ ] 主题 `ConfigProvider` 已联动（主色/语义色）
- [ ] `theme.override.css` 已注入（组件视觉 + 全局过渡 + 断点 + cursor-pointer）
- [ ] 定制设计系统未破坏业务逻辑与接口（覆盖层无侵入）
- [ ] mvp-prototype 已重启/构建（npm run dev / npm run build）
- [ ] 关键交互正常（上传/上传→AI 结果/对话/表格）
- [ ] 截图留存，做了 before/after 对照；无 console 报错

---

## 执行要点
1. 以上任一勾选项不满足 → **定位并修复**后重新注入/验证。
2. 无法满足的项（如无真实手机）→ 记录并降级处理，不得静默跳过。
3. 交叉引用：对比度细节看 `contrast_guard.md`；组件视觉看 `component_specs.md`；理论看 `figma_expertise.md`。

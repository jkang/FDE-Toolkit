# Figma 专业体验设计技巧 → 六维方法论文档（UX-Optimizer 参考）

本文档把 Figma 社区 / 专业设计系统的**核心体验设计技巧**，系统化为 6 个可执行维度，
供 UX-Optimizer 在做 MVP-prototype 定制设计时逐维落地。每个维度给出**目标 / 检查项 / 度量标准**，
确保"精心设计"可验证、可复现，而非凭感觉。

> 以下技巧为**通用专业手法**，与特定 design.md 无关，直接服务于产品级 MVP UI。

---

## 维度 1 · Layout & Grid（布局与栅格）
**目标**：建立有节奏、有结构、不随意的空间布局。

- **8pt 间距系统**：一切尺寸/边距/内距取 `4/8/12/16/24/32/48`，禁止随意 10/15 等奇数。
- **网格对齐**：元素列对齐、基线对齐；同类区块保持同一水平/垂直起始。
- **分组直觉**：关系近的元素间距**小**，区块之间间距**大**（关联分层）。
- **空白节奏**：交替"紧→疏"形成视觉呼吸感，避免全程等距带来的单调。
- **squint test（眯眼测试）**：眯眼仍能判断「最重要元素 / 次重要 / 分组」。

**检查项**：所有间距是否落在 8pt 体系；区块分组是否清晰；是否所有卡片布局雷同。

## 维度 2 · Visual Hierarchy & Typography（视觉层级与排版）
**目标**：让用户一屏内快速抓住重点，信息层级分明。

- **层级靠"字号+字重+色彩+空间"四重奏**，不只靠加粗。
- 一级标题大而醒目，正文小而稳定，标签大写/加字距/强调色。
- **字重分级**：标题 SemiBold，正文 Regular，次要 Light，避免全篇同权重。
- **行高**：正文 `1.5`，标题 `1.2`；标题字距 `-0.02em`。
- **信息优先级**：主要数字/结论突出，背景说明弱化（次要色）。

**检查项**：主要信息是否一眼可见；是否出现全篇同字号同字重；正文对比度是否足够。

---

## 维度 3 · Color & Contrast（色彩与对比度）
**目标**：色彩有语义、有层级、可访问。

- **语义色体系**：primary / success / warning / danger / info，各自职责明确不混用。
- **WCAG AA 对比度**：正文文字与背景对比 **≥ 4.5:1**；大字 ≥ 3:1。**色对一律从 `references/contrast_guard.md` 的标准语义色对取**。
- **禁用低对比反模式**：禁止 antd `gold`/`cyan`/`processing` 深底深字组合（正文常 <2:1）、浅灰字叠白底、深灰底配深灰字。
- **状态标签用"浅底深字"**：Tag / Alert 统一"软浅底 + 深字"模式（如 `#EAF2FB`/`#10213E` ≈14:1），输出前用 `scripts/contrast_check.py` 校验。
- **主色用量克制**：强调色用量控制在 5-10%，大面积用中性/品牌主色。
- **状态色不裸用**：配合图标/文字，不只靠颜色传达（色盲友好）。
- **中性色板**：正文、次要、边框、背景用一套收敛的中性色阶。

**检查项**：正文对比度是否达标；状态是否"色+图标+文字"三重表达；强调色是否克制；是否用 `scripts/contrast_check.py` 拒掉了低对比色对。

## 维度 4 · Component States（组件状态）
**目标**：每个可交互元素六态完备，任何情况下都不"死"。

- **六态**：`hover` / `active` / `focus` / `empty` / `loading` / `error`（+ `disabled`）。
- **focus 可见**：统一 Outline（强调色 `#5DB2E2` 风格），键盘用户可定位。
- **empty 态不裸**：给 icon + 说明 + 引导 CTA，而非空白。
- **loading 态反馈**：骨架屏优于转圈；给出"正在做什么"的文案。
- **error 态可恢复**：明确错误原因 + 下一步动作。

**检查项**：hover/focus/empty/loading/error 是否都有实现；empty 是否有引导。

---

## 维度 5 · Micro-interaction & Motion（微交互与动效）
**目标**：动效提供反馈与引导，但**克制、有目的**。

- **统一过渡**：`0.15s ease-out`；避免生硬跳变与过度弹簧。
- **动效有语义**：展开/收起、状态切换、加载反馈；不追求花哨。
- **克制原则**：企业级产品动效宜"润物细无声"，不做博眼球的强弹跳。
- **悬停反馈**：卡片/按钮悬停有轻微提升或阴影变化，提示可交互。

**检查项**：过渡是否统一 0.15s ease-out；动效是否服务于反馈/引导。

---

## 维度 6 · Accessibility & Responsive（可访问性与响应式）
**目标**：跨设备可用，且对多样用户友好。

- **断点**：375 / 768 / 1024 / 1440 四档，内容不溢出、不挤压。
- **可点击区域**：`cursor-pointer` 加到所有交互区；点击热区 ≥ 44px。
- **语义化**：标签、按钮有清晰文案；图标有 `aria-label` 或文字伴随。
- **缩放**：支持浏览器放大 200% 不破版。
- **双语/字符**：中英文混排、长文本不溢出、数字对齐。

**检查项**：断点是否生效；交互区是否有 `cursor-pointer`；放大后是否破版。

## 六维落地到 MVP-prototype 的映射

| 维度 | 落地到 mock-prototype 的位置 |
|------|------------------------------|
| 布局&栅格 | `theme.override.css` 间距变量 + 页面容器宽度 |
| 视觉层级&排版 | `tokens.js` 字体 token + 覆盖 Header/标题样式 |
| 色彩&对比度 | `tokens.js` 语义色 + 主题 `ConfigProvider` |
| 组件状态 | `component_specs.md` 六态规范 + `override.css` |
| 微交互&动效 | `override.css` 统一 transition |
| 可访问&响应式 | `override.css` 断点 media query + `cursor-pointer` |

> 完整 token 映射见 `design_token_schema.yaml`；组件级规范见 `component_specs.md`。

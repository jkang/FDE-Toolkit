# Agent Product Proposal Generator

本技能承接 FDE 方法**理需求 / 场景定义 / 挖知识 / 梳理本体**的既有产出，统一聚合为一份「**Agent 产品方案**」——一份可直接交给原型作者照单施工的**工程级设计文档**（Markdown）。

它不是模板填空，而是一个**翻译/聚合引擎**：把「知识挖掘出的规则、决策因子、阈值、硬/软约束」与「本体梳理出的实体/关系/动作/状态」，翻译成「产品形态、故事线 mock 数据、UI 交互、HITL 拦截、规则消费门禁」。

> [!IMPORTANT]
> **输出格式例外声明（本 Skill 不走视觉双重输出）**:
> 本 Skill 产物是**一份 Markdown 设计文档**（如「分仓智能补货 · Agent 产品方案 v2」），是给原型作者/开发照单施工的**规格文档**，**不是**可视化报告。因此**不**输出交互式 HTML，也不做 design.md 视觉渲染；仅输出单一 Markdown。此为双重输出规范的**显式例外**，仅适用于本 Skill。
>
> **输出路径与命名规范 (Output Path & Naming Convention)**:
> - **目录**: 产物属于具体 AI 场景 → **必须**放入 `<公司/业务名>/<场景名>/` 场景子目录（两层规范）。
> - **文件名**: 场景级 Markdown 命名 `[公司/业务名]-[场景名]-Agent产品方案.md`（例如：`X电商订舱-智能订舱Agent-Agent产品方案.md`）。
>
> **配套资产规范**:
> - 同一场景若需要结构化数据（供下游/复用），可另输出 `[公司/业务名]-[场景名]-Agent产品方案.schema.yaml`（可选，依据 `references/schema.yaml`）。

## 一、输入契约（上游产物）

本 Skill 依赖上游四项产出的**字段映射**，完整契约见 `references/input_contract.md`。缺失项允许**降级**（用现有产出代理 + 文档显式标注），但必须写明「用哪份代理」。

| 阶段 | 上游产物 | 关键字段 | 供本 Skill 使用 |
|---|---|---|---|
| 理需求 | 企业画像 / 业务现状全景 / 需求场景全景 | 业务领域、价值流、痛点、证据 | 产品定位、非目标、业务价值高光 |
| 场景定义 | AI 场景画布 + 数据/知识资产盘点 | 痛点、用户角色、输入输出、userGains/MoS、CKD | 定位一句话、使用者、KPI/价值、功能边界 |
| 挖知识 | 任务流程挖掘清单(L5) + 任务处理规则挖掘清单(五类规则) + To-be 流程/CKD/Agentic 工作流 | L5 任务、决策因子、阈值、优先级、硬/软约束 | 故事线 mock、功能上游来源、规则门禁、HITL 触发器 |
| 梳理本体 | Agent 本体设计（对象关系/行动边界/状态迁移） | 实体、关系、动作、HITL 边界、状态机 | 形态架构接触面、Agent 能/不能、HITL 拦截 |

## 二、核心设计引擎（本 Skill 的价值主张）

这是把它做成 Skill（而非模板）的关键——一组「规则 → 产品设计」的自动翻译规则，逐段驱动生成：

1. **决策因子 → 故事线 mock + HITL**：从决策模型类规则提取「因子 / 阈值 / 优先级」，注入演示剧本（用户→思考→调工具→输出）与 HITL 拦截条件。
2. **硬/软约束 → HITL 触发器**：硬约束（不可突破，如可发量）→「写入前必停 + 撤销窗口」；软约束（可仲裁，如成本优先）→「拦截提示 + 出处引用」。自动归类，不事无巨细拦截。
3. **五类规则 → 门禁承接表**：自动生成「规则类型 × SRP 是否识别 × 产品方案承接点 × 承接业务内容 × 备注」；操作流程类由 L5 深度任务回填（不重复）。
4. **必备交互 10 项 → 故事线/功能分配**：把 #1 流式 / #2 工具调用 / #3 思考折叠 / #4 内联组件 / #5 HITL / #6 撤销 / #7 出处引用 / #8 状态徽章 / #9 错误态 / #10 空态 分发到各故事线与功能。
5. **本体对象/动作 → 形态架构接触面**：实体、关系、动作映射为相邻产品的「读/写」接触面与主交互区编排（入口/主交互/周边支撑三区）。
6. **场景画布 MoS/痛点 → 定位一句话 + 价值高光**：从 userGains/MoS 提炼「四件套·定位一句话」与每条故事线的「业务价值高光」。
7. **阶段闭环 → 故事线划分**：按 L3/L5 阶段（询价→推荐→订舱→单证→跟踪）切成 4 条有头有尾的演示故事线（可含异常/错误/撤销分支）。

## 三、输出架构（8 段式）

对齐范例，产出文档含 **meta 头部 + 8 个主体段**。每段字段、数据来源、生成规则如下（字段规范见 `references/schema.yaml`）：

| 段 | 内容 | 数据来源与生成规则 |
|---|---|---|
| meta | 版本 / 更新日期 / 对应业务阶段 / 方法论依据 / 输入依据 | 由执行上下文与输入清单填充 |
| 1 总览 | 做了什么 / 重点看什么 / 为什么关注 / 当前洞察 / 需要 FDE 做什么 | 其余各段自动**回填总结**；「当前洞察」提炼规则结构一致性（如「硬约束集中、软优先级少量」） |
| 2 产品定位 | 迭代范围 / 产品形态(B2B自用型) / **四件套**（定位一句话、非目标、主要使用者、Agent 人格） | 定位源自场景画布 MoS；非目标=场景边界反向排除相邻系统/相邻画布；Agent 人格=身份+语气+能力边界（来自本体行动边界） |
| 3 产品形态架构图 | mermaid 三大区（入口/主交互/周边支撑）+ 相邻产品接触面 | 引擎⑤：本体实体/关系/动作 → 接触面读/写；相邻产品只画接触面不画协议字段 |
| 4 原型演示故事线（默认 4 条） | 每条 = 价值高光 / 对应阶段 / 演示剧本 / UI组件+必备交互 / 业务内容来源 | 引擎①⑦④：按 L3/L5 阶段切 4 条；mock 数据取 SKP 决策因子/阈值（脱敏）；交互标注 #1~#10 |
| 5 业务功能与 UI 组件清单 | 大表（功能名/一句话价值/绑定角色/渲染层/触发方式/UI组件+内容/用户操作/关联故事线/上游来源）+ 必备交互 10 项承诺 | 引擎④：把 10 项交互分发到功能与故事线；上游来源填具体 L5 任务/规则/术语条目 |
| 6 Agent 行为设计 | 6.1 是谁（开场/语气/能力边界） 6.2 让用户看到什么 6.3 何时停下等用户 6.4 怎么撤销与兜底 | 引擎②⑤：硬约束→必停+撤销；软约束→提示+出处；本体行动边界→能力承诺；10 项交互→「看到什么」 |
| 7 SKP 五类规则消费门禁 | 表（规则类型 / SRP 是否识别 / 产品方案承接点 / 承接业务内容 / 备注） | 引擎③：决策/模板/术语/关键信息提取/关联关系五类各承接；操作流程类由 L5 回填不重复 |
| 8 待确认问题清单 | 表（# / 待确认问题 / 用途与影响） | 自动归纳「阈值口径 / 边界 / 视觉基底 / 相邻系统边界」等悬空决策点 |

## 四、工作流 SOP

1. **确认输入**：读取上游产物清单（理需求 / 场景定义 / 挖知识 / 本体）；缺失项向用户确认或标注降级（写明代理）。
2. **抽取知识底座**：从挖知识/本体中提取「规则、决策因子、阈值、硬软约束、实体、关系、动作、状态机」，作为翻译引擎的动力源。
3. **逐段汇编**：按「输出架构」表，以「核心设计引擎」①→⑦ 逐段生成（先 2 产品定位 → 3 形态架构 → 4 故事线 → 5 功能清单 → 6 Agent 行为 → 7 门禁 → 8 待确认 → 1 总览回填）。
4. **生成 Markdown**：按 `templates/proposal_template.md` 骨架装配，充实各段内容与 mermaid/表格。
5. **校验**：按「质量校验 Checklist」自查（可用 `scripts/build_proposal.py` 校验结构与列/要素齐全性），不通过则修。
6. **交付落位**：写入 `<公司/业务名>/<场景名>/<公司名>-<场景名>-Agent产品方案.md`，向主 Agent 返回产物清单与「待 FDE 确认」问题。

## 五、质量校验 Checklist（每条须满足）

- [ ] **meta**：版本 / 更新日期 / 方法论依据 / 输入依据齐全。
- [ ] **第 2 段四件套**：定位一句话、非目标、主要使用者、Agent 人格(身份/语气/能/不能)。
- [ ] **第 3 段**：mermaid 含「入口区 / 主交互区 / 周边支撑区」三区；相邻产品只标读/写接触面。
- [ ] **第 4 段**：≥4 条故事线，每条含「价值高光 / 对应阶段 / 演示剧本 / UI组件+必备交互 / 业务内容来源」五要素；剧本写清 用户→思考→调工具→输出→(HITL/错误/撤销)。
- [ ] **第 5 段**：功能表 9 列齐全；必备交互 10 项(#1~#10)每项至少分配到一处。
- [ ] **第 6 段**：6.1 能力边界与本体行动边界一致；6.3 HITL 与挖知识「硬约束」一一对应（硬→必停，软→提示）；4 个触发类别齐全。
- [ ] **第 7 段**：五类规则(决策/模板/术语/关键信息提取/关联关系)齐全；操作流程类由 L5 回填不重复；每类注明「必须承接 / 必须强化承接」。
- [ ] **第 8 段**：待确认问题 ≥2，含用途与影响。
- [ ] **命名/落位**：`<公司>-<场景名>-Agent产品方案.md` 置于 `<公司/业务名>/<场景名>/`，不落公司根目录。

# Interview Record Integrator (访谈记录整理 · 待确认稿)

把一场现状访谈的**三份原始材料**（调研提纲、人工记录、AI 录音记录）合并整理成一份
**可核对、可溯源的事实归位稿**——供业务方逐条核对后再进入下游分析（价值流 / 问题定义 / 机会挖掘）。
**适用于任何客户、业务线或岗位的现状访谈**，不限定行业与角色。

> **性质**：本技能产出的是**调研原始素材的结构化归位**，不是分析结论。
> 它的价值在于「客观、可核对、可溯源」，因此**只归位事实，不做任何提炼与判断**。
> 分析、归因、机会识别由下游技能（`business-process-deep-analyzer` / `problem-definition` 等）承担。

> 定位与上下游：
> - **上游输入**：调研提纲（`*-现状访谈提纲.md`）、现场人工记录（`*-人工记录.md`）、AI 录音转写（`*-录音记录.md`）。
> - **本 Skill**：三源合并 → 按提纲逐题事实归位 → 输出《访谈信息整理（待确认稿）》。
> - **下游衔接**：`business-process-deep-analyzer`（现状泳道图）、`problem-definition`（问题定义 8 要素）、
>   `ai-opportunity-map-generator` / `opportunity-definition`（机会挖掘）——均以本稿核对后的内容为准。

> **与相邻 Skill 的边界（避免误触发）**
> - 本 Skill **只整理访谈原始记录**，不产出泳道图 / 问题定义 / 机会地图等分析产物；分析请用上述下游技能。
> - 本 Skill **不覆盖桌研 / 公开资料调研**（属 `company-ai-maturity-research` / `business-research`）。
> - 本 Skill **不做访谈设计**（提纲编写属访谈前的准备工作，不属本技能范围）。

> [!IMPORTANT] 全局规范（输出形态 / 输出路径 / 铁律）
> **① 输出形态（显式例外）**：本 Skill **只输出单一 Markdown**，不出 YAML、不出 HTML。
> 原因是产物为叙事型事实稿、而非结构化数据；按 `skill-creator` 规范，属需显式声明的输出例外。
>
> **② 输出路径与命名**：
> - 目录：与原始材料同目录（通常为 `<客户>/<场景>/调研记录/`）。
> - 文件名：`[业务线/场次]-访谈信息整理.md`（如 `华东区-访谈信息整理.md`）。
> - **禁止**把真实访谈产物写进本技能的 `examples/`（examples/ 仅放脱敏演示样例）。
>
> **③ 铁律（违反即返工）**：见文末「输出呈现铁律」。本 Skill 的核心是
> `references/caveats.md` 的注意事项清单，**必须逐条执行**。

## 一、核心原则：三源合并 → 事实归位

| 输入 | 作用 | 使用方式 |
|---|---|---|
| **调研提纲**（`*-现状访谈提纲.md`） | 提供**骨架与题号**（章节、问题号；如有价值流分段对照则一并使用） | 作为输出的一级结构；逐题对应 |
| **人工记录**（`*-人工记录.md`） | 现场**骨架 + 关键词**（常写在提纲模板上，有错字、碎片、跳跃） | 先按题号打底，标出每题已有的关键词 |
| **AI 录音记录**（`*-录音记录.md`） | 逐句转写，提供**细节、数字、原话**（含多人对话与转写错误） | 逐句回填到对应题号，补细节、补数字、摘原话 |

**归位逻辑**：以提纲为骨架，人工记录打底，录音补全 → 每一题最终写成「受访者所述的事实」。

**两种归位口径**（按材料情况选择，并在文首说明）：
1. **提纲归位**（默认）：有提纲时，严格按提纲的章节与题号逐题归位。
2. **链路归位**：无提纲、或提纲不适用时，按该场次的**业务链路**归位
   （链路随场景而定，如「现状数据 → 信息收集 → 分析判断 → 机会识别 → 行动制定 → 执行反馈」）。
   详见 `references/output-structure.md`。

## 二、★ 注意事项（本 Skill 的核心）

> 完整清单与反例见 `references/caveats.md`。以下为必须逐条执行的硬规则。

- **A. 只做事实归位**：仅记录受访者所述 facts；不提炼、不推断、不评价、不给方案建议；
  区分「应该这样」与「实际这样」。
- **B. 未提及必须显式标注**：未答 / 未问到的题项一律写「未提及」/「本次访谈未涉及」；
  **留空等于臆造**。
- **C. 录音转写错误——两级处理**：
  - **C1 明显错别字 / 误词 → 直接纠正**（能凭上下文确定正确写法，且不涉及专有名词归属），
    并在文末「已纠正项」注明 `原文 → 纠正`。
  - **C2 人名 / 产品名 / 机构名等专有名词无法确证 → 不擅改**，统一在**文末「待澄清」清单**
    集中列出：位置 / 转写原文 / 疑似正确 / 需澄清什么。
  - **C3 产品名铁律**：以权威产品知识库（官方产品资料 / 内部产品清单）为准；
    口述产品名不在库中的标 `[待核实]`，**不得作为结论依据**。不臆造、不顺手补齐。
- **D. 身份与在场人**：受访人未具名 → 「姓名待确认」；称呼冲突 → 以人工记录 / 录音自述为准并标待确认；
  **区分主受访人 vs 在场他人**（他人的补充须标明来源，如「XX 补充」）。
- **E. 数字与口径**：口述数字内部有出入 → 保留原口径 + 注明「为受访人口述，内部有小出入，以此口径为准」；
  单位 / 口径不明 → 标「单位 / 口径待确认」。不臆造、不推算补齐。
- **F. 三源交叉**：人工记录与录音冲突时，以录音原话为准或并列标注差异；文首列明记录来源。
- **G. 事实 / 感受 / 期望三分**：如提纲定义了打标约定则沿用；否则用 🟢 事实 / 🟡 感受 / 🔵 期望；
  期望与设想须标「属受访人设想，尚未落地」。
- **H. 剔除过程讨论**：采访人之间的方法讨论、场务对话、与本次访谈无关的闲聊，一律不进正文。
- **I. 原话金句照抄不加工**：提纲附「原话摘录」项，照抄受访者原话。

## 四、工作流 SOP

### Step 1 · 收齐并识别三件套
- 按 `references/input-contract.md` 识别同场次的提纲、人工记录、录音记录三份文件。
- 缺件时按契约降级（如无提纲则改用链路归位），并在文首说明。

### Step 2 · 读提纲，建骨架
- 提取章节、题号、必问项（★）、量化项（▸）；如有价值流分段对照，一并记下。
- 无提纲 → 采用链路结构。

### Step 3 · 人工记录归位打底
- 把人工记录的关键词按题号填入骨架；标出每题「已有内容 / 空白」。

### Step 4 · 录音逐句回填
- 通读录音转写，把细节、数字、原话回填到对应题号；
- **同步执行 C 级处理**：明显错字直接纠正（记入「已纠正项」），专有名词存疑登记到「待澄清」；
- 剔除过程讨论与场务对话（H）。

### Step 5 · 打标与缺口标注
- 事实 / 感受 / 期望三分（G）；未提及项显式标注（B）；
- 数字口径按 E 处理。

### Step 6 · 汇总文末清单
- 生成「待确认与本次未涉及」「待澄清（录音转写存疑）」「已纠正项」三块。

### Step 7 · 输出与自检
- 输出单一 Markdown 到原始材料同目录；
- 按 `references/caveats.md` 逐条自检 + 文末 QA 清单。

## 八、输出呈现铁律（通用 · 强制）

> 产出是给**客户 / 业务方**看的最终报告，不是过程记录。以下五条**违反即返工**。

1. **语言**：一律用**严谨、克制的中文业务咨询语言**——有一说一；**有观点必给依据**（数据 / 规则 / 来源 / 口径）。
   禁止 AI 味大词与空话堆砌（「赋能、闭环、抓手、深度融合、全方位、数智化」等无实指表述）。
2. **禁止多余英文备注**：中文标题 / 小节后**不得**追加英文装饰。系统名 / 字段名 / 标准缩写（SAP、SKU、KPI、ROI）可保留；不造装饰性英文。
3. **只输出结论与依据**：**禁止**把过程讨论写进正文——与用户的对话 / 反馈、修订说明、跨行业类比的过程推理等一律不进正文。
4. **口径与边界**：不确定的推断标 `[推断]` 并给依据；不臆造数据；假设与阈值标注「待访谈回填」。
5. **交付前自检**：逐段问「读者能否据此核对 / 这是否属于我们内部讨论」——不能核对或属内部讨论的内容，删除或移出正文。

> **本 Skill 的显式例外**：本稿是**待业务方核对的调研事实底稿**，因此
> 「待确认 / 未提及 / 待澄清（转写存疑）/ 已纠正项」**是交付物的核心内容，必须保留**；
> 上述第 3 条所禁止的是**采访人之间的过程讨论与制作说明**，不含这些核对标记。

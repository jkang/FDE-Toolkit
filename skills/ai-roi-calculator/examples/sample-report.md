## 六、结论与决策建议
- **结论**：按当前假设 ROI 为负，直接立项**不划算**。
- **何时转正（临界分析）**：用户数同比放大即大幅改善——
  | 场景 | 活跃用户 | ROI | 回收期 |
  | --- | ---: | ---: | ---: |
  | ×1（现状） | 150 | -26% | >36mo |
  | ×2 | 300 | +47% | 25.3mo |
  | ×4 | 600 | +194% | 13.2mo |
  - 判断：只要稳态活跃用户能到 **300+**，项目即转正；这是立项前必须验证的核心风险点。
- **建议**：
  1. **先做 MVP 验证渗透率**：仅当能证明活跃用户可达 300+ 才产品化，否则停留在轻量工具。
  2. **压固定投入**：产品化研发+迭代+基础设施占 75%——考虑复用现有中台、用现成 API 而非自建算力、降低定制化集成。
  3. **关注敏感项**：收益对"用户数×频次"最敏感；成本对"研发人力/迭代投入"最敏感。两大风险都指向**小规模场景不划算**。

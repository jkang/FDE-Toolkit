# OSM Map Generator  v2

将战略分析和前端可视化分为两段：
1. LLM 理解业务描述 → 一次性输出含底层场景的完整 YAML
2. Python 编译引擎 → 读取 YAML → 精准布局 → 独立单文件 HTML

> [!IMPORTANT]
> **双重输出规范 (Dual Output Standard)**: 
> 当你使用此 Skill 时，必须**同时**输出两个部分：
> 1. **结构化 YAML**: 用于下一步的自动化处理和数据存档。
> 2. **交互式 HTML**: 用于最终用户的直观审查与演示。
> 
> **输出路径与命名规范 (Output Path & Naming Convention)**:
> - **目录**: 输出到 `<公司/业务名>/` 公司/业务级目录；若产物属于**具体 AI 场景**（如某场景的测试数据集 / 故事地图 / Agent 本体等），**必须**放入 `<公司/业务名>/<场景名>/` 场景子目录（两层规范；场景级文件名需含场景名，如 `[公司]-[场景]-[业务类型].html`）。
> - **文件名**: HTML 文件名必须反映内容，格式为 `[公司/业务名]-[业务类型].html` (例如：`ZX机车海外销售-OSM战略地图.html`)。
> 
> **视觉设计规范 (Visual Design Standard)**:
> - **样式风格**: 默认按本 skill `references/` 内示例的视觉规范输出。
> - **底色模式**: 默认使用 **浅色底 (Light Mode)**。
> - **页面布局**: HTML 内容区撑满容器宽度（width: 100%），Header 采用统一精简样式（左侧标题+副标题、右侧操作按钮），内容超出屏幕时容器内可上下左右滚动。

## 工作流 SOP

### Step 1 · 解析输入
- 阅读用户描述，识别行业领域，内化核心痛点与期望目标

### Step 2 · 生成 YAML
- 读取 `references/osm_prompts.md` 获取全部设定（角色+字段规范+示例）
- 使用完整 prompt 指导 LLM 生成结构化 YAML（字段说明见 `references/schema.yml`）
- 将生成内容保存至**客户目录** `<公司/业务名>/[公司/业务名]-OSM战略地图.yaml`（命名遵循上方「输出路径与命名规范」；`examples/` 仅存放演示样例，**禁止**将客户产物存入其中）

### Step 3 · 校验 YAML（选做）
- 确认文件以 `title:` 开始，无 Markdown 代码块外壳
- 确认每个子目标都有 `relatedScenarios.scenarios`（≥ 2 条）
- 如有格式问题，脚本会自动剥除 ` ``` ` 标记后重试解析

### Step 4 · 编译 HTML
```bash
# 生产：用客户目录中的 YAML 编译 HTML（HTML 与 YAML 同放客户目录）
python3 scripts/build_osm.py "<公司/业务名>/[公司/业务名]-OSM战略地图.yaml" "<公司/业务名>/[公司/业务名]-OSM战略地图.html"

# 渲染自检（演示）：examples/ 仅供验证渲染流程，不存放客户产物
python3 scripts/build_osm.py examples/saas_complex.yaml examples/_osm_demo.html
```

### Step 5 · 交付
- 通知用户用浏览器打开生成的 HTML 文件即可查看完整可视化

## build_osm.py v2 核心能力

| 能力 | 实现方式 |
|------|----------|
| 防呆 YAML 解析 | 正则自动剥除 ` ```yaml ` 和 ` ``` ` 代码块包裹 |
| 模板引擎分离 | Jinja2 + `templates/osm_layout.html`，样式修改无需动算法代码 |
| 动态高度测算 | 根据 `scenarios` 条数精算业务场景卡片高度，避免节点重叠 |
| SVG 贝塞尔连线 | 自动为父目标→子目标绘制虚线路径，关系直观 |
| `config` 生效 | `config.height.objectiveScore` 真正控制目标行高度 |
| 多层树支持 | level ≥ 2 的节点自动折叠入 sub-lane，不破坏整体布局 |

## 输出呈现铁律（通用 · 强制）

> 产出是给**客户 / 业务方**看的最终报告，不是过程记录。以下六条**违反即返工**。

1. **语言**：一律用**严谨、克制的中文业务咨询语言**——有一说一；**有观点必给依据**（数据 / 规则 / 来源 / 口径）。禁止 AI 味大词与空话堆砌（「赋能、闭环、抓手、深度融合、全方位、数智化」等无实指表述）。
2. **禁止多余英文备注**：中文标题 / 小节后**不得**追加英文装饰（如「业务模式全景 BUSINESS MODEL LANDSCAPE」）。系统名 / 字段名 / 标准缩写（SAP、IF005、DOS、SKU、SLA）可保留；不造装饰性英文。
3. **只输出结论与依据**：**禁止**把过程讨论写进正文——与用户的对话 / 反馈、修订说明、`【不依据原始 idea】` 这类过程标注、跨行业类比的过程推理（如「与快消品的渠道逻辑不同」）、「待确认 / 此处待补 / 讨论点」等制作层信息，一律不进正文。
4. **口径与边界**：不确定的推断标 `[推断]` 并给依据；不臆造数据；假设与阈值标注「领域专家假设值 · 待访谈回填」。
5. **交付前自检**：逐段问「读者能否据此做决策 / 这是否属于我们内部讨论」——不能决策或属内部讨论的内容，删除或移出正文。
6. **精炼优先**：**只保留必要段落**——删除一切辅助描述、方法论 / 流程 / 制作层说明、示例性长文与重复表述；模板用**最小占位符**，不得用示例内容充数。

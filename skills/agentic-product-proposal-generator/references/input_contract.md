# 上游输入契约（Input Contract）
# 说明：本 Skill 消费 FDE 方法「理需求 / 场景定义 / 挖知识 / 梳理本体」的既有产出。
# 每个输入文件需用 Read 读取其中的关键字段，映射到 产品方案的对应段落。
# 缺失项允许「降级」：用现有产出代理，并在文档 meta.input_sources 中显式标注「用哪份代理」。

---

## 1. 理需求（业务与价值定位）

**上游产物**：业务主体与画像 / 业务现状全景 / 需求场景全景（或 NSM 分析 / 价值段现状泳道图（L3/L4） / 体验旅程图 / 服务蓝图）。

**关键字段 → 本 Skill 用途**：

| 关键字段 | 映射到 |
|---|---|
| 业务领域 / 价值流 | 第1段·迭代范围、第1段·产品形态 |
| 业务痛点 / 证据 | 第1段·定位一句话、第3段·每条故事线的业务价值高光 |
| 端到端流程 / 现状泳道图 | 第2段·相邻产品接触面、第4段·功能 |

**降级规则**：若只有「价值段现状泳道图」而无「需求场景全景」，用其环节痛点/规则代——仍可产出定位与非目标，value 高光需标注「基于流程推断」。

---

## 2. 场景定义（场景与边界）

**上游产物**：AI 场景画布（AI Canvas，10 维）+ 数据/知识资产盘点（CKD）。

**关键字段 → 本 Skill 用途**：

| 关键字段 | 映射到 |
|---|---|
| userRoles / userPains | 第1段·主要使用者（目标用户）、第1段·定位一句话、第1段·Agent 人格语气、第1段·场景痛点 |
| aiInput / dataKnowledge | 第2段·主交互区（场景输入·触发入口 / 知识）、第3段·演示剧本 mock、第4段·功能 |
| workflow / modelUsage | 第2段·编排、第5段·让用户看到什么（核心能力·方案假设） |
| aiOutput / systemIntegration | 第3段·Agent 输出（场景输出·交付出口）、第4段·UI 组件（集成系统） |
| productType / businessGains | 第1段·产品形态、第1段·定位一句话、第3段·业务价值高光（KPI） |
| 场景边界 / 相邻系统 | 第1段·非目标、第2段·相邻产品 |

> **术语注**：AI Canvas schema 中收益字段为 `businessGains`（业务收益，须非常量化，见 `ai-canvas-generator` 的 schema）。“MoS”= Measure of Success（成功度量）为 FDE 线下课程用语，与 `businessGains` 指向同一字段——产物文档一律写 `businessGains`。

**降级规则**：若缺「数据/知识资产盘点」，则由 CKD 映射或本体数据字段代，功能清单的「上游来源」标注「依据画布字段推断」。

---

## 3. 用户画像与典型旅程（第 3 段故事线骨架）

**上游产物**：用户画像与典型旅程（`persona-journey-designer` 产出，`<公司>-<场景>-用户画像与旅程.md`）。

**关键字段 → 本 Skill 用途**：

| 关键字段 | 映射到 |
|---|---|
| 画像（主用户 / 次要用户） | 第3段·故事线的「用户画像」、第4段·功能「绑定角色」 |
| 典型场景（画像 × 场景） | 第3段·**故事线划分单位**（每个场景 = 一条故事线） |
| Job Story（当…我想要…以便…） | 第3段·故事线的「用户目标」 |
| 起点 → 终点（目标触发 → 目标完成） | 第3段·故事线的**端到端边界** |
| 产品介入点 | 第3段·故事线中 Agent 承担的步骤、第4段·功能 |

**硬性规则**：第 3 段故事线**必须**以本产物的「画像 × 场景」为单位，覆盖**主用户全部一期场景 + 1–2 条次要用户场景**；**禁止**按 L3/L5 流程阶段切片（会把原型切碎）。

**降级规则**：若缺《用户画像与典型旅程》，先按 AI 画布 `userRoles` + To-be 流程临时推导画像与场景，并在第 7 段标注「建议补做用户画像与旅程」。

---

## 4. 挖知识（规则与约束——本 Skill 的动力源）

**上游产物**：任务流程挖掘清单（L3→L4→L5 深度任务）+ 任务处理规则挖掘清单（五类规则）+ To-be 流程 / CKD 映射 / Agentic 工作流。

**关键字段 → 本 Skill 用途**：

| 关键字段 | 映射到 |
|---|---|
| L5 深度任务（actor：agent/mixed/human） | 第3段·故事线的**业务内容来源**、第4段·功能上游来源、第2段·交互编排 |
| 决策模型类规则（决策因子 / 阈值 / 优先级） | 第3段·演示剧本 mock、第5段·HITL 触发、第6段·门禁表 |
| 硬约束（不可突破：可发量/对外下发/负量） | 第5段·何时停下（写入前必停 + 撤销）、第6段·门禁 |
| 软约束（可仲裁：成本优先/配送时效） | 第5段·何时停下（提示 + 出处引用）、第6段·门禁 |
| 模版范例类（表单/报告模板、必填字段） | 第4段·功能 UI 组件、第6段·门禁 |
| 术语字典类 / 关键信息提取要点 | 第4段·术语 hover 卡、第6段·门禁（必须强化承接） |
| 关联关系类（实体关联网络） | 第2段·接触面、第6段·门禁 |
| Agentic 工作流（活动序列/编排模式/护栏/失败兜底） | 第5段·让用户看到什么、第5段·撤销与兜底 |

**降级规则**：若缺「任务处理规则挖掘清单」，可用 L5 任务表的 `ruleType` 列 + 决策因子作代理，门禁表标注「基于任务表推断」，并把「需要 FDE 确认」写入第7段。

---

## 5. 梳理本体（Agent 的结构与行为边界）

**上游产物**：Agent 本体设计（对象关系 → 行动边界 → 状态迁移）+ Agentic 工作流（若分开）。

**关键字段 → 本 Skill 用途**：

| 关键字段 | 映射到 |
|---|---|
| 对象（实体）/ 关系 | 第2段·主交互区、第2段·相邻产品接触面、第4段·功能 |
| 行动边界（能做/不做、HITL 门） | 第5段·Agent 能力边界、第5段·何时停下、第3段·HITL 拦截 |
| 状态迁移（状态机：待装柜/已开船/待补件…） | 第4段·状态徽章(#8)、第3段·故事线状态流转 |
| HITL 边界 / 防旁路 | 第5段·何时停下（必停）、第4段·HITL 拦截(#5) |

**降级规则**：若缺「本体设计」，用 To-be 流程/边界代，第5段能力边界标注「依据流程推断」，并纳入待确认。

---

## 6. 输入清单读取顺序（SOP 第 1~2 步）

建议按「本体 → 挖知识 → 用户画像与旅程 → 场景定义 → 理需求」顺序读取（先取深/近边界，再取价值/定位），用临时文件传递中间结果：
1. 本体：抽取实体/动作/HITL/状态 → 决定第2段、第5段骨架。
2. 挖知识：抽取 L5/规则/因子/硬软约束 → 决定第4、6段骨架与第3段的业务内容来源。
3. 用户画像与旅程：抽取「画像 × 场景 × 旅程」→ 决定**第3段故事线骨架（端到端）**。
4. 场景定义：抽取画布 `businessGains`（MoS＝Measure of Success／成功度量，课程用语）等字段 → 决定第1段四件套、第3段价值高光。
5. 理需求：抽取价值流/痛点 → 补齐第1段。

任何一步缺文件 → 中止并向用户确认，或降级后写入第7段「待确认问题」。

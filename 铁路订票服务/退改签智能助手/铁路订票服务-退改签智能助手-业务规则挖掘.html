退改签阶梯费率规则 使用点 · 计算退改签阶梯费率
①决策因子
开车前时间差：当前时间到发车时间的时间差（决定费率档位） (来源 运行时计算)
票种/席别：全价票/学生票/儿童票等特殊票种规则 (来源 订单 + 规则库)
最低收费：退票费最低收取标准（2 元） (来源 12306 规则库)
责任归属：因铁路责任（晚点/停运）不收费 (来源 运行监控 + 规则库)
→
②逻辑分支
开车前 8 天（含）以上 → → 不收取退票费
开车前 48 小时以上、不足 8 天 → → 收取 5% 退票费
开车前 24 小时以上、不足 48 小时 → → 收取 10% 退票费
开车前不足 24 小时 → → 收取 20% 退票费
因铁路责任（晚点/停运） → → 全额退票/免费改签
→
③分支动作
按开车前时间差档位、票种与责任归属确定性计算退改签费用。
→
④冲突仲裁
计费走确定性规则引擎，不靠 LLM 算钱；最低收费 2 元；改签后再次退票按改签后票面口径。
例外/HITL：特殊票种或规则盲区 → 转规则兜底/人工；计费与说明不一致 → 以规则引擎结果为准。
改签方案寻优排序规则 使用点 · 结合偏好与成功率排序
①决策因子
旅客偏好：尽早出发/不接受换乘/席别必须一致等约束 (来源 会话上下文)
余票可得性：候选方案的实时余票与候补概率 (来源 余票库存)
历史改签成功率：历史同场景改签成功率大数据 (来源 大数据模型)
票价差与损失：改签成本与退票损失的对比 (来源 计费结果)
→
②逻辑分支
满足全部偏好且有直达 → → 高分推荐（Top 1）
部分满足偏好 → → 标注权衡后推荐
无满足偏好的方案 → → 放宽条件重算并说明
→
③分支动作
按偏好与历史成功率加权排序，输出 Top 3 并标注权衡。
→
④冲突仲裁
偏好冲突时优先级：尽早出发 > 席别一致 > 不换乘；硬约束（席别一致）不可突破。
例外/HITL：偏好冲突/无候选 → 给出权衡说明或放宽条件重算。
退改签场景识别规则 使用点 · 识别退改签场景类型
①决策因子
外部事件：列车晚点/停运状态 (来源 运行监控 API)
用户操作：用户在订单页发起的退票/改签动作 (来源 用户操作事件)
订单状态：订单是否可退/可改（时间、状态约束） (来源 票务核心)
→
②逻辑分支
列车晚点/停运 → → 运行变更处置路径
用户发起退票 → → 退票处置路径
用户发起改签 → → 改签处置路径
→
③分支动作
依据外部事件、用户操作与订单状态识别退改签场景并选定处置路径。
→
④冲突仲裁
运行变更优先于用户主动操作；订单不可退改时直接提示并终止。
例外/HITL：意图不明 → 追问澄清；订单已失效 → 提示并终止。
关联延伸服务处置规则 使用点 · 同步注销/更新关联服务使用点 · 跨业务一致性校验
①决策因子
跨业务关联协议：票务与餐饮/约车/接送站/行程单的关联关系 (来源 关联协议库)
主票处置结果：主票退票/改签后的车次与席别变化 (来源 票务核心)
关联订单状态：关联服务订单的当前状态 (来源 订单协同中心)
→
②逻辑分支
主票退票 → → 关联服务同步注销/退款
主票改签（车次变化） → → 关联服务按协议更新或注销
无关联服务 → → 不适用
→
③分支动作
依据跨业务关联协议同步处置关联延伸服务并做一致性校验。
→
④冲突仲裁
以主票处置结果为准，关联服务同步处置；一致性校验不通过需回滚或转人工。
例外/HITL：关联不明/处置失败 → 转客服人工处理。

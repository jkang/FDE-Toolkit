# 业务本体：铁路订票服务-退改签智能助手-Agent本体设计
领域：铁路票务 / 售后
Agent 角色：退改签智能助手（Railway Refund/Change Assistant）
场景：针对铁路出行「退票、改签、运行变更」高焦虑售后场景，从场景识别、规则转译、方案推荐到主票与关联服务一体化处置的端到端退改签场景

## 1. 核心业务对象与概念边界
### 票务订单（Ticket Order） [核心对象]
- 定义：铁路票务订单，是退改签处置的业务主线与主键锚点
- 属性定义：
  * order_no (string) - 订单号
  * train_no (string) - 车次
  * seat_class (string) - 席别
  * fare (number) - 票价
  * depart_time (datetime) - 发车时间
  * order_status (enum)（可选值：valid / changed / refunded / expired） - 订单状态
- 关键概念边界（不可混淆）：
  ⚠️ 订单有效 ≠ 可退改（受时间与状态约束）
  ⚠️ 改签后订单状态变为 changed，票价多退少补
### 运行变更事件（Run Change Event） [事件对象]
- 定义：列车晚点/停运等铁路责任事件，是自动拉起服务的外部触发
- 属性定义：
  * train_no (string) - 车次
  * event_type (enum)（可选值：delay / cancellation） - 事件类型
  * delay_minutes (number) - 晚点时长
- 关键概念边界（不可混淆）：
  ⚠️ 运行变更属铁路责任 → 全额退票/免费改签
  ⚠️ 运行变更优先于用户主动操作触发
### 退改签费率规则（Fee Rule） [参考对象]
- 定义：12306 退改签阶梯费率与特殊票种规则
- 属性定义：
  * tier (string) - 时间差档位（8天/48h/24h/24h内）
  * rate (number) - 费率
  * min_fee (number) - 最低收费（2 元）
- 关键概念边界（不可混淆）：
  ⚠️ 计费走确定性规则引擎，LLM 不算钱
  ⚠️ 因铁路责任不收费
### 改签方案（Change Plan） [事件对象]
- 定义：候选改签方案（直达/候补/换乘），含排序与风险评估
- 属性定义：
  * plan_id (string) - 方案标识
  * plan_type (enum)（可选值：direct / waitlist / transfer） - 方案类型
  * match_score (number) - 偏好匹配度
  * risk_level (enum)（可选值：low / medium / high） - 风险等级
  * price_diff (number) - 票价差
- 关键概念边界（不可混淆）：
  ⚠️ 候选方案 ≠ 可执行方案（需旅客选定并放行）
  ⚠️ 风险等级必须有依据，不得无依据乐观标注
### 退改记录（Refund/Change Record） [事件对象]
- 定义：主票退票/改签的执行记录
- 属性定义：
  * record_no (string) - 退改记录号
  * action_type (enum)（可选值：refund / change） - 退票或改签
  * fee_charged (number) - 收取费用
  * execute_status (enum)（可选值：pending / success / failed） - 执行状态
- 关键概念边界（不可混淆）：
  ⚠️ 退改交易是对外承诺，必须人工放行
  ⚠️ 交易失败不得无限制自动重试
### 延伸服务订单（Related Service Order） [参考对象]
- 定义：与票务订单关联的餐饮/约车/接送站/行程单订单
- 属性定义：
  * service_no (string) - 关联服务单号
  * service_type (enum)（可选值：catering / ride / pickup / itinerary） - 服务类型
  * dispose_status (enum)（可选值：not_applicable / pending / disposed / failed） - 处置状态
- 关键概念边界（不可混淆）：
  ⚠️ 主票退改 ≠ 关联服务已处置
  ⚠️ 关联服务未一致性校验通过前不得标记完成
### 乘车人（Passenger） [参考对象]
- 定义：订单乘车人信息与偏好
- 属性定义：
  * name (string) - 姓名
  * id_no (string) - 证件号（脱敏）
  * preferences (string) - 出行偏好（尽早出发/不接受换乘/席别一致）
- 关键概念边界（不可混淆）：
  ⚠️ 多人订单需按人拆分处置
### 通知（Notification） [事件对象]
- 定义：运行变更 Push 卡片与处置结果通知
- 属性定义：
  * notice_id (string) - 通知标识
  * notice_type (enum)（可选值：run_change_push / dispose_result） - 通知类型
  * push_status (enum)（可选值：pending / sent / failed） - 推送状态

## 3. 行动边界限制（情境 - 证据 - 合法/禁止动作）
### 情境：退改交易执行前放行
描述：旅客选定方案后，准备发起主票退票/改签交易
必须核实的证据：
  - [票务订单] 订单有效且可退改
  - [改签方案] 旅客已选定方案
  - [费率规则] 费用已确定性计算并经旅客确认
✅ 合法动作（允许执行）：
  - 发起主票退票/改签交易
  - 交易失败记录并转人工重试
❌ 禁止动作（严禁执行，防范错误假设）：
  - 未经旅客确认即发起退改交易 （禁止原因：退改是对外承诺与资金动作，必须人工放行）
  - 对交易失败无限制自动重试 （禁止原因：高风险资金动作需人工确认，避免重复退改）
⚠️ 异常触发规则：
  - 当满足条件【交易失败】 → 必须执行：记录原因 → 转人工确认后重试
### 情境：规则转译与费用说明
描述：AI 将阶梯费率规则转译为当前订单下的大白话说明
必须核实的证据：
  - [费率规则] 确定性计费结果
  - [票务订单] 时间差与票种
✅ 合法动作（允许执行）：
  - 按结论-依据-建议结构转译
  - 输出可视化费用对比
❌ 禁止动作（严禁执行，防范错误假设）：
  - 由 LLM 估算或修改金额 （禁止原因：计费必须走确定性规则引擎，说明与结果必须一致）
⚠️ 异常触发规则：
  - 当满足条件【特殊票种/规则盲区】 → 必须执行：转规则兜底/人工，标注待确认
### 情境：关联延伸服务一体化处置
描述：主票退改后同步处置关联的餐饮/约车/接送站/行程单服务
必须核实的证据：
  - [跨业务关联协议] 识别出关联服务清单
  - [主票处置结果] 主票退改已完成
✅ 合法动作（允许执行）：
  - 按协议同步注销/更新关联服务
  - 一致性校验并输出处置清单
❌ 禁止动作（严禁执行，防范错误假设）：
  - 未校验一致性即标记处置完成 （禁止原因：遗漏关联服务会造成旅客损失）
⚠️ 异常触发规则：
  - 当满足条件【关联不明/处置失败】 → 必须执行：转客服人工处理并留痕

## 4. 状态流转与全局护栏（Workstreams & States）
### 执行流（Workstream）：识别流
描述：从运行变更事件/用户操作到场景与订单识别的执行流
锚点对象：运行变更事件（Run Change Event）、票务订单（Ticket Order）
状态节点及迁移路径：
  - 状态：事件到达 (i_event)
    状态定义：运行变更事件或用户操作到达
    可用的状态转移路径：

  - 状态：场景已识别 (i_identified)
    状态定义：场景与订单已识别，进入规则转译
🔒 全局不可绕过护栏规则：

  - 订单不可退改时直接提示并终止
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【转译流】 满足条件【场景已识别】，则受到影响：规则转译流程可开始
### 执行流（Workstream）：转译流
描述：从计费到规则转译与费用对比的执行流

  - 状态：已转译 (tr_translated)
    状态定义：规则已转译并输出费用对比
🔒 全局不可绕过护栏规则：
  - 计费走确定性规则引擎，LLM 不算钱
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【推荐流】 满足条件【费用已明确】，则受到影响：方案推荐可结合成本
### 执行流（Workstream）：推荐流

锚点对象：改签方案（Change Plan）、票务订单（Ticket Order）
状态节点及迁移路径：
  - 状态：候选已检索 (r_candidates)
    状态定义：直达/候补/换乘候选方案已检索
    可用的状态转移路径：
      * --[结合偏好与成功率排序] (核实证据: Top 3 方案与排序依据生成)--> 到达状态 已排序 (性质: 正常迁移)
  - 状态：已排序 (r_ranked)
    状态定义：Top 3 方案已排序并评估风险
    可用的状态转移路径：

  - 状态：已选定 (r_selected)

  - 硬约束（席别一致）不可突破
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【处置流】 满足条件【方案已选定】，则受到影响：主票退改与关联处置可开始
### 执行流（Workstream）：处置流

  - 状态：处置失败 (d_failed)
    状态定义：交易/关联处置失败，转人工
    可用的状态转移路径：
      * --[人工确认后重试] (核实证据: 人工确认并重试成功)--> 到达状态 主票已处置 (性质: 异常恢复)
  - 状态：已确认 (d_confirmed)
    状态定义：处置结果已确认并通知，退改签闭环
🔒 全局不可绕过护栏规则：

  - 关联服务未一致性校验通过前不得标记完成
🔗 跨流依赖关系：

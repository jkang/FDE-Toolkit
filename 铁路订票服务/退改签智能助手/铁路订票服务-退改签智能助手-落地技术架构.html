5 条链共享读写本体 / 按需调用 MCP
共享底座
🧱 本体（确定性底座）

读 R：票务订单（识别/处置）、费率规则（转译）、延伸服务订单（关联处置）。
写 W：退改记录（处置回写）、关联服务处置状态（同步回写）、通知与行程（确认回写）。
对象 / 关系 / 状态迁移 + 业务事实；计费与校验走确定性规则，不靠 LLM 猜事实。

🔌 MCP / 外部系统

调用点：票务核心交易（退/改/订）、实时列车运行监控、全业务订单协同中心（餐饮/约车/接送站/行程单）、Push / 消息网关、智能客服工单系统、12306 退改签费率知识库。
仅需要外部读写的步骤才走 MCP。

📚 知识库 / RAG

检索点：12306 退改签阶梯费率知识库、改签方案寻优经验、跨业务关联处置协议、铁路票务退改签术语字典。
计费走规则引擎而非向量检索；费率条款、寻优经验、关联协议、术语走 RAG。

🩷 异常池（人工终审）：订单不可退改 / 特殊票种 / 规则盲区 / 无候选方案 / 偏好冲突 / 交易失败 / 关联处置不一致 / Loop 超限 → 升级人工，附上下文摘要。

失败 / 降级 / 兜底

触发处理类型
运行监控事件丢失兜底为用户主动发起 + 事件重连 1 次fallback / retry
订单不存在 / 已失效提示并终止，不进入退改流程fallback
特殊票种 / 规则盲区转规则兜底 / 人工，标注待确认，不臆造费率escalate
无候选方案 / 偏好冲突给出权衡说明或放宽条件重算fallback
票务核心退改交易失败记录返回 → 人工确认后重试，禁止无限制自动重试retry / escalate
关联服务处置失败 / 一致性不一致回滚或转客服人工处理并留痕escalate
Push 推送失败重试，不影响处置结果记录retry

KPI 锚定（链路 → 指标）

退改签自助率① 识别 + ② 转译 + ③ 推荐 + ④ 处置　目标 ≥95%
决策耗时③ 方案寻优　15–20 分钟 → 秒级
高峰期改签成功率③ 方案寻优（历史成功率排序）
客服进线量⑤ 异常建单转客服　标准场景分流
关联服务遗漏损失④ 一体化处置 + 一致性校验

护栏落点

计费走确定性规则引擎LLM 不算钱；说明与规则引擎结果必须一致
对外承诺必须人工放行选择改签方案、发起退改交易前必停
交易失败不得无限制自动重试高风险资金动作，须人工确认后重试
关联服务未一致性校验通过不得标记完成避免遗漏关联服务造成损失
硬约束不可突破席别一致等硬约束不可被偏好排序覆盖
⚠️ 口径待确认：阶梯费率档位与特殊票种规则是否与最新 12306 政策一致；方案寻优偏好优先级；跨业务关联处置口径。
⚠️ 基线待回填：退改签自助率 ≥95%、高峰期改签成功率、决策耗时的基线口径。
⚠️ MCP 边界：本方案把票务核心/运行监控/订单协同/Push/工单画成 MCP 外部调用；若确认「MCP=0，数据全部来自绑定本体」，则归入本体/内部服务并标 N/A。

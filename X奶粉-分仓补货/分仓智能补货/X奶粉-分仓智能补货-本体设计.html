核心对象
分货方案（Allocation Plan）

Agent 在多种约束下求解出的基地仓到销售仓分配方案，核心字段为分配量，不等于京慧建议量，也不等于实际发货量

plan_version enum
A_balanced / B_priority
alloc_qty number
分配量（罐）
stock_days_after number
分配后库存天数 DOS
status enum
draft / pending_confirm / confirmed / dispatched
⚠️ 概念边界
≠ 分配量 ≠ 京慧建议量：分配量是多约束求解结果，偏离建议量必须人工确认
≠ 分配量 ≤ 可发量：超可发量的方案不允许下发
≠ 方案已确认 ≠ 补货单已下发：确认与对外下发是两个门禁
核心对象
补货单（Replenishment Order）

由确认后的分货方案生成的标准调拨单，用于下发物流调度与财务核算，是执行与结算的凭证

order_no string
补货单号（全链路主键锚点）
from_site string
发货基地仓编码
to_site string
收货销售仓编码
qty number
调拨数量
status enum
pending_check / pending_dispatch / dispatched / in_transit / received / closed / cancelled
⚠️ 概念边界
≠ 补货单下发 ≠ 实际发货：下发只代表指令写入物流调度/财务
≠ 补货单数量 ≠ 实际入库数量：可能有正常损耗或差异
≠ 下发后 10 秒内可撤销，撤销后回到待下发状态
核心对象
库存天数（DOS）

衡量各仓库存可支撑天数的核心指标，Agent 据其判定缺口等级与分配后库存健康度

dos_value number
DOS=(库存+在途+分配)/日均销售计划
level enum
red / yellow / blue / normal
⚠️ 概念边界
≠ DOS 分子含在途与已分配，不等于现货/日均
≠ DOS>60 且无促销才是积压预警，促销期不判积压
≠ 阈值边界（7/14/60 天）冲突需人工确认

情境 1
分配方案生成后需人工确认或微调
Agent 已求解出多版分配方案，但分配量涉及业务责任与促销经验，需物流计划岗确认/微调后才可进入补货单生成
📋 Required Evidence
分货方案（allocation_plan）

缺口告警（shortage_alert）
红/黄/蓝分级与促销抑制已标注
京慧建议量（jinghui_suggestion）
偏离项已列出并进入待确认清单
✅ Valid Actions
展示多版分配方案与各版本差异供人工选择
接受人工微调并重新执行多约束校验
记录人工修改原因并留痕
确认后将方案状态置为已确认
❌ Invalid Actions
未经人工确认直接将分配方案下发
原因：分配量涉及业务责任，静默下发会产生错误承诺与责任缺失
人工修改后跳过约束重校验
原因：修改可能超出可发量/安全水位约束，必须重新校验
修改分配量不留修改原因
原因：缺少留痕无法复盘与追责
⚠️ Exception Triggers
当：约束冲突导致无法求解可行方案
→ 输出备选方案并升级人工复核
当：人工修改超出可发量/安全水位约束
→ 退回重算并提示冲突项

# 业务本体：X奶粉-分仓智能补货-Agent本体设计
领域：供应链分仓补货
Agent 角色：分货方案助理（Replenishment Allocation Assistant）
场景：X奶粉事业部从基地仓到销售分仓的智能分货补货执行场景：Agent 拉取全仓库存与需求、识别缺口、多约束求解分配方案、生成校验并下发补货单、跟踪在途与入库、生成复盘调参建议，人工只在关键确认点介入。

## 1. 核心业务对象与概念边界
### 分货方案（Allocation Plan） [核心对象]
- 定义：Agent 在多种约束下求解出的基地仓到销售仓分配方案，核心字段为分配量，不等于京慧建议量，也不等于实际发货量
- 属性定义：
  * plan_version (enum)（可选值：A_balanced / B_priority） - 方案版本（均衡版/优先版）
  * alloc_qty (number) - 分配量（罐）
  * stock_days_after (number) - 分配后库存天数 DOS
  * status (enum)（可选值：draft / pending_confirm / confirmed / dispatched） - 方案状态
- 关键概念边界（不可混淆）：
  ⚠️ 分配量 ≠ 京慧建议量：分配量是多约束求解结果，偏离建议量必须人工确认
  ⚠️ 分配量 ≤ 可发量：超可发量的方案不允许下发
  ⚠️ 方案已确认 ≠ 补货单已下发：确认与对外下发是两个门禁
### 补货单（Replenishment Order） [核心对象]
- 定义：由确认后的分货方案生成的标准调拨单，用于下发物流调度与财务核算，是执行与结算的凭证
- 属性定义：
  * order_no (string) - 补货单号（全链路主键锚点）
  * from_site (string) - 发货基地仓编码
  * to_site (string) - 收货销售仓编码
  * qty (number) - 调拨数量
  * status (enum)（可选值：pending_check / pending_dispatch / dispatched / in_transit / received / closed / cancelled） - 补货单状态
- 关键概念边界（不可混淆）：
  ⚠️ 补货单下发 ≠ 实际发货：下发只代表指令写入物流调度/财务
  ⚠️ 补货单数量 ≠ 实际入库数量：可能有正常损耗或差异
  ⚠️ 下发后 10 秒内可撤销，撤销后回到待下发状态
### 库存天数（DOS） [核心对象]
- 定义：衡量各仓库存可支撑天数的核心指标，Agent 据其判定缺口等级与分配后库存健康度
- 属性定义：
  * dos_value (number) - DOS=(库存+在途+分配)/日均销售计划
  * level (enum)（可选值：red / yellow / blue / normal） - 缺口等级
- 关键概念边界（不可混淆）：
  ⚠️ DOS 分子含在途与已分配，不等于现货/日均
  ⚠️ DOS>60 且无促销才是积压预警，促销期不判积压
  ⚠️ 阈值边界（7/14/60 天）冲突需人工确认

- 定义：京慧一盘货给出的初始建议补货量，仅作为分配参考基线，不构成约束

  * expire_date (date) - 效期
- 关键概念边界（不可混淆）：
  ⚠️ 大日期判定口径待业务专家二轮验证，当前标注概念级
  ⚠️ 大日期库存不应再向该仓增配同效期商品
### 缺口告警（Shortage Alert） [事件对象]
- 定义：Agent 按 DOS 分级生成的缺口/积压告警事件，驱动分配优先级
- 属性定义：
  * level (enum)（可选值：red / yellow / blue） - 告警等级
  * trigger_dos (number) - 触发时的 DOS
- 关键概念边界（不可混淆）：
  ⚠️ 红色告警是补货优先级，不等于必须足额满足（受可发量约束）
  ⚠️ 蓝色积压预警在促销期被抑制
### 在途台账（In-transit Ledger） [事件对象]
- 定义：Agent 抓取 TMS 定位生成的在途监控记录，含位置、状态、预计到货与延误判定
- 属性定义：
  * order_no (string) - 关联补货单号
  * delay_hours (number) - 延误小时数
  * position (string) - 当前定位
- 关键概念边界（不可混淆）：
  ⚠️ 在途台账 ≠ 已入库：货物未验收前不计入可发量
  ⚠️ 延误>24h/48h 才触发预警拉人
### 入库验收记录（Receiving Record） [事件对象]
- 定义：WMS 入库验收结果，含运单、实收数量与差异率，触发库存同步与差异处理
- 属性定义：
  * waybill_no (string) - 运单号
  * received_qty (number) - 实收数量
  * diff_rate (number) - 差异率
- 关键概念边界（不可混淆）：
  ⚠️ 实收数量才是可发量同步的依据，调拨数量不是
  ⚠️ 差异未关闭前差异数量不得计入可发量
### 复盘报告（Review Report） [事件对象]
- 定义：月度复盘事件，含时效达成率/缺货缓解率/周转率/差异率与调参建议
- 属性定义：
  * period (string) - 复盘周期
  * metrics (string) - 指标集合
- 关键概念边界（不可混淆）：
  ⚠️ 复盘结论 ≠ 参数已生效：调参须审批后下一周期生效
  ⚠️ 多项指标矛盾时以时效达成率优先

## 2. 对象关系依赖（Relationships）
- 【分仓销售计划（Sales Plan）】 --(驱动, 基数 1:N)--> 【分货方案（Allocation Plan）】
  说明：分仓销售计划决定需求基准，驱动分配方案的分配量求解
- 【促销计划（Promotion Plan）】 --(约束, 基数 N:N)--> 【分货方案（Allocation Plan）】
  说明：促销放量上浮分配量并抑制积压预警
- 【京慧建议量（Jinghui Suggestion）】 --(参考, 基数 1:N)--> 【分货方案（Allocation Plan）】
  说明：京慧建议量作为分配参考基线，偏离须人工确认
- 【缺口告警（Shortage Alert）】 --(触发, 基数 1:N)--> 【分货方案（Allocation Plan）】
  说明：缺口告警按红/黄/蓝驱动分配优先级
- 【大日期库存（Big-date Inventory）】 --(约束, 基数 N:N)--> 【分货方案（Allocation Plan）】
  说明：大日期/临期库存作为新鲜度约束限制分配方向
- 【仓库（Warehouse）】 --(供给, 基数 1:N)--> 【仓库（Warehouse）】
  说明：一个基地仓可向多个销售仓供给，方向为基地仓→销售仓
- 【产品/SKU（Product）】 --(归属, 基数 N:N)--> 【仓库（Warehouse）】
  说明：SKU 库存归属于具体仓库，site_code×product_code 为分析粒度
- 【分货方案（Allocation Plan）】 --(生成, 基数 1:N)--> 【补货单（Replenishment Order）】
  说明：确认后的分货方案生成标准化补货单
- 【补货单（Replenishment Order）】 --(触发, 基数 1:N)--> 【在途台账（In-transit Ledger）】
  说明：补货单下发后触发在途台账跟踪
- 【在途台账（In-transit Ledger）】 --(触发, 基数 1:N)--> 【入库验收记录（Receiving Record）】
  说明：在途货物到仓后触发 WMS 入库验收
- 【入库验收记录（Receiving Record）】 --(更新, 基数 N:1)--> 【库存天数（DOS）】
  说明：按实收同步可发量并更新 DOS
- 【入库验收记录（Receiving Record）】 --(回馈, 基数 N:N)--> 【复盘报告（Review Report）】
  说明：入库差异与时效数据回馈月度复盘
- 【复盘报告（Review Report）】 --(约束, 基数 N:1)--> 【安全水位（Safety Stock）】
  说明：复盘调参建议经审批后更新安全水位

## 3. 行动边界限制（情境 - 证据 - 合法/禁止动作）
### 情境：分配方案生成后需人工确认或微调
描述：Agent 已求解出多版分配方案，但分配量涉及业务责任与促销经验，需物流计划岗确认/微调后才可进入补货单生成
必须核实的证据：
  - [分货方案（allocation_plan）] 方案含建议量/可发量/分配量/分配后库存天数与约束校验结果
  - [缺口告警（shortage_alert）] 红/黄/蓝分级与促销抑制已标注
  - [京慧建议量（jinghui_suggestion）] 偏离项已列出并进入待确认清单
✅ 合法动作（允许执行）：
  - 展示多版分配方案与各版本差异供人工选择
  - 接受人工微调并重新执行多约束校验
  - 记录人工修改原因并留痕
  - 确认后将方案状态置为已确认
❌ 禁止动作（严禁执行，防范错误假设）：
  - 未经人工确认直接将分配方案下发 （禁止原因：分配量涉及业务责任，静默下发会产生错误承诺与责任缺失）
  - 人工修改后跳过约束重校验 （禁止原因：修改可能超出可发量/安全水位约束，必须重新校验）
  - 修改分配量不留修改原因 （禁止原因：缺少留痕无法复盘与追责）
⚠️ 异常触发规则：
  - 当满足条件【约束冲突导致无法求解可行方案】 → 必须执行：输出备选方案并升级人工复核
  - 当满足条件【人工修改超出可发量/安全水位约束】 → 必须执行：退回重算并提示冲突项
### 情境：分配量偏离京慧建议量
描述：多约束求解结果与京慧建议量存在明显偏离（如促销放量上调 12%），写入前必须人工确认
必须核实的证据：
  - [京慧建议量（jinghui_suggestion）] 建议量数值与来源时点
  - [分货方案（allocation_plan）] 分配量及偏离比例
  - [促销计划（promo_plan）] 偏离是否由促销放量等业务原因解释
✅ 合法动作（允许执行）：
  - 列出偏离项、偏离比例与可能原因
  - 提示人工确认偏离后再写入
  - 确认后记录偏离原因与确认人
❌ 禁止动作（严禁执行，防范错误假设）：
  - 静默用分配量覆盖京慧建议量 （禁止原因：偏离未被业务确认，可能掩盖促销或数据异常）
  - 把京慧建议量当作硬约束强行对齐 （禁止原因：建议量只是参考，强行对齐会牺牲全局优化与服务水平）
⚠️ 异常触发规则：
  - 当满足条件【偏离比例超出经验阈值且无业务原因可解释】 → 必须执行：标记异常并拉人核查数据口径
### 情境：补货单对外下发
描述：补货单已校验通过，即将下发物流调度与财务核算，属对外动作，必须人工放行
必须核实的证据：
  - [补货单（replenishment_order）] 收发仓/SKU/数量/时效 4 项校验全部通过
  - [分货方案（allocation_plan）] 方案状态为已确认
✅ 合法动作（允许执行）：
  - 展示补货单与校验结果供人工确认
  - 人工确认后下发并保留 10 秒撤销窗口
  - 撤销时回滚物流调度与财务侧写入
❌ 禁止动作（严禁执行，防范错误假设）：
  - 校验未通过即下发 （禁止原因：库存不足/时效超期/字段缺失会造成下游履约失败）
  - 跳过人工确认自动下发 （禁止原因：对外下发为合规红线，必须人工放行）
⚠️ 异常触发规则：
  - 当满足条件【下发后 10 秒内人工撤销】 → 必须执行：回滚下发，补货单回到待下发状态
  - 当满足条件【下游系统写入失败】 → 必须执行：自动重试，超限则拉人并保留上下文
### 情境：基地仓可发量不足或物流预警缺失
描述：分货求解时基地仓可发量无法覆盖缺口，或 TMS 物流预警数据未接通，需生成备选或降级处理
必须核实的证据：
  - [缺口告警（shortage_alert）] 缺口数量与受影响仓×SKU
  - [仓库（warehouse）] 周边基地仓可发量、仓网距离与运输时效
  - [在途台账（in_transit_ledger）] 物流预警/运输状态是否可用
✅ 合法动作（允许执行）：
  - 按可发量约束优先拆分多仓补足
  - 生成成本/时效/库存均衡的多套备选方案
  - 物流预警缺失时按历史时效估算并显式标注降级
  - 备选均不可行时升级人工并建议调整周期
❌ 禁止动作（严禁执行，防范错误假设）：
  - 可发量不足时仍按原目标足额分配 （禁止原因：超出可发量约束会导致下发失败或超发现象）
  - 物流预警缺失时静默按正常时效处理 （禁止原因：未标注降级会误导人工决策，掩盖数据缺口）
⚠️ 异常触发规则：
  - 当满足条件【所有周边基地仓均无法补足缺口】 → 必须执行：升级人工，评估拆分批次或调整补货周期
  - 当满足条件【TMS 物流预警数据未接通】 → 必须执行：按历史运输时效估算，显式标注降级并建议人工复核
### 情境：入库实收与调拨数量存在差异
描述：WMS 入库验收显示实收数量与调拨数量不一致，需按差异率阈值判定正常损耗或生成差异单
必须核实的证据：
  - [入库验收记录（receiving_record）] 运单号、实收数量、差异率
  - [补货单（replenishment_order）] 应发/调拨数量
✅ 合法动作（允许执行）：
  - 按实收数量同步可发量与 DOS
  - 差异率≤0.5% 标记为正常损耗
  - 差异率>0.5% 生成差异处理单并推送财务与仓管
  - 破损率>1% 生成独立异常工单
❌ 禁止动作（严禁执行，防范错误假设）：
  - 按调拨数量而非实收数量同步库存 （禁止原因：会造成账面库存虚高，影响后续分配与履约）
  - 差异未关闭即将差异数量计入可发量 （禁止原因：差异原因未查清，计入可发量会放大错误）
⚠️ 异常触发规则：
  - 当满足条件【差异率>0.5%】 → 必须执行：生成差异单并拉人追责
  - 当满足条件【破损率>1%】 → 必须执行：生成独立异常工单并拉人
### 情境：安全水位调整审批
描述：复盘发现指标不达标需调整安全水位，但水位调整影响服务水平与周转，须人工审批
必须核实的证据：
  - [复盘报告（review_report）] 时效达成率/缺货缓解率/周转率/差异率与短板分析
  - [安全水位（safety_stock）] 当前各仓安全水位与渠道/区域差异
✅ 合法动作（允许执行）：
  - 按区域+渠道计算差异化水位调整建议
  - 列出调整对服务水平与周转的预估影响
  - 审批通过后参数下一周期生效
❌ 禁止动作（严禁执行，防范错误假设）：
  - 未审批直接调整安全水位 （禁止原因：水位影响服务水平，越过审批会造成不可控的缺货风险）
  - 仅凭单一指标调整水位 （禁止原因：多项指标矛盾时须以时效达成率优先，单指标调整可能顾此失彼）
⚠️ 异常触发规则：
  - 当满足条件【指标异常恶化或多指标冲突】 → 必须执行：拉人审批，由物流计划岗裁决调整方向

## 4. 状态流转与全局护栏（Workstreams & States）
### 执行流（Workstream）：货源评估与数据准备
描述：从拉取全仓库存与需求到形成口径校验通过的分货数据底表的执行流
锚点对象：分仓销售计划（Sales Plan）、库存天数（DOS）、缺口告警（Shortage Alert）
状态节点及迁移路径：
  - 状态：待汇总 (dp_pending)
    状态定义：分货周期启动，库存/在途/需求数据尚未拉齐，仅可见零散来源
    可用的状态转移路径：
      * --[拉取全仓库存与在途并形成供需视图] (核实证据: 现货/在途/待检/合格库存与销售计划均已拉取成功)--> 到达状态 供需视图就绪 (性质: 正常迁移)
      * --[检查数据完整性] (核实证据: 存在数据缺失或口径异常)--> 到达状态 数据异常待处理 (性质: 异常分支)
  - 状态：供需视图就绪 (dp_view_ready)
    状态定义：全国供需视图已生成，DOS 已计算，缺口分级待完成
    可用的状态转移路径：
      * --[计算 DOS 并判定缺口等级] (核实证据: DOS 与红/黄/蓝分级结果已生成)--> 到达状态 缺口分级完成 (性质: 正常迁移)
      * --[检查 DOS 阈值边界] (核实证据: DOS 落在 7/14/60 天边界且无法自动判定)--> 到达状态 数据异常待处理 (性质: 异常分支)
  - 状态：缺口分级完成 (dp_gap_graded)
    状态定义：缺口/积压分级完成，分货数据底表口径校验通过，可进入方案编制
    可用的状态转移路径：
      * --[汇总并校验分货数据底表口径] (核实证据: 可发量/待检/合格/在途/生产备货率/大日期 6 项口径校验通过)--> 到达状态 底表就绪 (性质: 正常迁移)
  - 状态：底表就绪 (dp_table_ready)
    状态定义：分货数据底表准备完毕，可供多约束分配求解
  - 状态：数据异常待处理 (dp_data_issue)
    状态定义：数据缺失或口径冲突，需调度组复核
    可用的状态转移路径：
      * --[调度组修正口径后重试] (核实证据: 口径冲突已解决，数据重新拉取成功)--> 到达状态 待汇总 (性质: 异常恢复)
🔒 全局不可绕过护栏规则：
  - 待检与合格库存必须分开取值，不得混用
  - 在途必须取「在途总量」，不得取「已下发未发货」
  - 底表口径未校验通过前不得进入分配求解
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【分货方案编制】 满足条件【底表就绪状态 dp_table_ready】，则受到影响：分配方案编制解除等待，可开始备货率与分配量求解
### 执行流（Workstream）：分货方案编制
描述：从备货率计算到多约束分配方案确认的执行流（全场景 P0）
锚点对象：分货方案（Allocation Plan）、京慧建议量（Jinghui Suggestion）、促销计划（Promotion Plan）、安全水位（Safety Stock）
状态节点及迁移路径：
  - 状态：待求解 (al_ready)
    状态定义：底表就绪，备货率与优先级待计算
    可用的状态转移路径：
      * --[计算备货率与多约束分配量] (核实证据: 生产备货率/订单完成率/目标备货率与分配量已生成)--> 到达状态 方案草稿 (性质: 正常迁移)
  - 状态：方案草稿 (al_draft)
    状态定义：多版分配方案已生成，含京慧偏离项与约束校验结果，待人工确认
    可用的状态转移路径：
      * --[人工确认或微调并重新校验] (核实证据: 物流计划岗确认，修改原因留痕，约束重校验通过)--> 到达状态 方案已确认 (性质: 正常迁移)
      * --[检查约束求解结果] (核实证据: 约束冲突无法求解，或人工修改超出可发量/安全水位)--> 到达状态 约束冲突 (性质: 异常分支)
  - 状态：方案已确认 (al_confirmed)
    状态定义：分配方案经人工确认，可生成补货单并移交执行跟踪流程（下发门禁在 ws_execution）
  - 状态：约束冲突 (al_conflict)
    状态定义：多约束无可行解或人工修改越约束，需生成备选或退回重算
    可用的状态转移路径：
      * --[生成备选方案或退回重算] (核实证据: 备选方案生成或约束调整完成)--> 到达状态 方案草稿 (性质: 异常恢复)
🔒 全局不可绕过护栏规则：
  - 分配量不得超过可发量
  - 目标备货率封顶 100%
  - 分配量偏离京慧建议量必须人工确认后方可写入
  - 人工修改分配量后必须重新校验多约束
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【货源评估与数据准备】 满足条件【底表未就绪或口径未校验】，则受到影响：分配方案编制被阻塞，不能开始求解
  - 自身在该工作流时，若另一执行流 【执行跟踪与入库同步】 满足条件【方案确认并生成补货单】，则受到影响：执行跟踪流程可开始，等待补货单下发
### 执行流（Workstream）：执行跟踪与入库同步
描述：从补货单下发的在途跟踪到入库验收、库存同步与差异处理的执行流
锚点对象：补货单（Replenishment Order）、在途台账（In-transit Ledger）、入库验收记录（Receiving Record）、库存天数（DOS）
状态节点及迁移路径：
  - 状态：已下发待发货 (ex_dispatched)
    状态定义：补货单已下发物流调度/财务，等待实际发货
    可用的状态转移路径：
      * --[抓取 TMS 在途定位] (核实证据: 在途台账已生成，含车辆/位置/状态)--> 到达状态 在途运输中 (性质: 正常迁移)
      * --[检查运输状态] (核实证据: 延误超过 24h/48h 或运输异常)--> 到达状态 延误/破损待处理 (性质: 异常分支)
  - 状态：在途运输中 (ex_in_transit)
    状态定义：货物在途，Agent 持续跟踪定位并预警延误/破损
    可用的状态转移路径：
      * --[到仓并触发入库验收] (核实证据: WMS 入库验收记录生成)--> 到达状态 入库验收中 (性质: 正常迁移)
      * --[检查延误与破损] (核实证据: 延误>24h/48h 或破损率>1%)--> 到达状态 延误/破损待处理 (性质: 异常分支)
  - 状态：入库验收中 (ex_receiving)
    状态定义：WMS 验收中，核对实收与调拨数量，判定差异
    可用的状态转移路径：
      * --[同步库存指标并关闭调拨单] (核实证据: 差异率≤0.5%，可发量/DOS 已按实收同步)--> 到达状态 收货完成 (性质: 正常迁移)
      * --[记录差异并生成差异单] (核实证据: 差异率>0.5%)--> 到达状态 差异处理中 (性质: 异常分支)
  - 状态：差异处理中 (ex_discrepancy)
    状态定义：差异单已生成并推送财务/仓管，受影响数量暂不计入可发量
    可用的状态转移路径：
      * --[跟进并关闭差异单] (核实证据: 差异单已关闭或经授权处理)--> 到达状态 收货完成 (性质: 异常恢复)
  - 状态：延误/破损待处理 (ex_delayed)
    状态定义：运输延误或破损，已预警并拉人处理
    可用的状态转移路径：
      * --[异常解除后继续跟踪] (核实证据: 延误/破损异常已处理)--> 到达状态 在途运输中 (性质: 异常恢复)
  - 状态：收货完成 (ex_complete)
    状态定义：库存指标已同步，调拨单已关闭，可进入复盘
🔒 全局不可绕过护栏规则：
  - 未完成入库验收前不得按调拨数量计入可发量
  - 差异未关闭前差异数量不得计入可发量
  - 延误/破损不得通过修改状态跳过，必须有实际处理证据
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【分货方案编制】 满足条件【补货单尚未下发】，则受到影响：执行跟踪流程等待，无在途台账
  - 自身在该工作流时，若另一执行流 【复盘与参数迭代】 满足条件【收货完成且差异关闭】，则受到影响：复盘流程可获得完整时效与差异数据
### 执行流（Workstream）：复盘与参数迭代
描述：从月度指标统计到调参建议审批生效的执行流
锚点对象：复盘报告（Review Report）、安全水位（Safety Stock）
状态节点及迁移路径：
  - 状态：待复盘 (rv_pending)
    状态定义：月度周期结束，复盘指标尚未统计
    可用的状态转移路径：
      * --[统计复盘指标并生成报告] (核实证据: 时效达成率/缺货缓解率/周转率/差异率已统计)--> 到达状态 复盘完成 (性质: 正常迁移)
  - 状态：复盘完成 (rv_reported)
    状态定义：复盘报告与调参建议已生成，待人工审批
    可用的状态转移路径：
      * --[人工审批调参建议] (核实证据: 物流计划岗审批通过)--> 到达状态 参数已生效 (性质: 正常迁移)
      * --[检查指标恶化] (核实证据: 指标异常恶化或多指标冲突)--> 到达状态 指标恶化待决策 (性质: 异常分支)
  - 状态：参数已生效 (rv_approved)
    状态定义：调参建议审批通过，安全水位等参数下一周期生效
  - 状态：指标恶化待决策 (rv_risk)
    状态定义：指标异常恶化，需人工裁决调整方向
    可用的状态转移路径：
      * --[人工裁决后重出调参建议] (核实证据: 调整方向已明确)--> 到达状态 复盘完成 (性质: 异常恢复)
🔒 全局不可绕过护栏规则：
  - 复盘结论不等于参数已生效，调参必须经审批后下一周期生效
  - 多项指标矛盾时以时效达成率优先于周转优化
  - 安全水位调整不得绕过审批直接生效
🔗 跨流依赖关系：
  - 自身在该工作流时，若另一执行流 【执行跟踪与入库同步】 满足条件【执行跟踪数据不完整】，则受到影响：复盘指标失真，需等待数据补齐后再复盘
  - 自身在该工作流时，若另一执行流 【分货方案编制】 满足条件【调参审批通过】，则受到影响：下一周期分配方案使用更新后的安全水位与参数

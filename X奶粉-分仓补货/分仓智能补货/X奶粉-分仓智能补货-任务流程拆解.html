🤖 Agent 		WMS 入库验收(运单/实收/差异率) 差异记录、差异处理单 决策模型类·入库差异判定规则 差异率>0.5% → 生成差异单并拉人追责

🤝 混合执行 		各仓库存天数、渠道差异、区域类型 差异化安全水位建议 决策模型类·安全水位设置经验 服务水平与周转冲突 → 人工审批

🤖 Agent 		分仓大日期库存、效期 临期预警 决策模型类·大日期判定经验[待二轮验证] 大日期判定口径待二轮验证 → 标注概念级

🤝 混合执行 		时效达成率、缺货缓解率、周转率、入库差异率 月度复盘报告、调参建议 模版范例类·复盘报告模板 指标异常恶化 → 拉人审批；多项指标矛盾以时效达成优先
🔁输入输出如何闭环 下游衔接

💡挖掘的关键

为什么这样拆？

每个 L5 各自只有一个核心动词，产出可观察，并可独立挂接一类业务规则；焦点 L4 下钻后，多约束分配从『一个笼统的分配』变成『算量→选仓→出版本→确认』四个可分别校验与追溯的动作。

挖掘的关键不是改写名称

挖掘的关键不是改写名称，而是把专家真实执行的动作顺序、输入输出、判断依据和异常链路结构化——尤其是把『京慧建议量→人工微调→重新校验』这条隐性决策链显性化。

🧱 本体（确定性底座）

读 R：现货/在途/待检/合格库存（缺口识别）、分仓销售计划 + 促销计划（DOS/备货率）、京慧建议量（分配参考基线）、仓网/产品主数据 + 安全水位（选仓与约束）、大日期库存（新鲜度约束）、缺口告警（分配优先级）。
写 W：分货方案 allocation_plan（分配量）、补货单 replenishment_order（下发）、在途台账 / 入库验收记录（执行）、可发量 / DOS（库存同步）、复盘报告 / 安全水位（调参）。
对象 / 关系 / 状态迁移 + 业务事实；Skill 读写本体，不靠 LLM 猜事实。分配量≠京慧建议量、补货单下发≠实际发货、实收≠调拨数量三处口径以本体为准。

🔌 MCP / 外部系统

调用点：现货/在途库存系统（拉数）、京慧一盘货（只读建议量）、奶粉分仓补调系统（读写分配量）、APS/S&OP（读供应上限）、TMS（在途定位）、WMS（入库验收）、物流调度系统（下发）、财务核算系统（下发）。
仅需要外部读写的步骤才走 MCP；读走 MCP、写回走本体。

📚 知识库 / RAG

检索点：分仓补货业务口径词典（rdict_01）、五类规则库（rd_01~rd_08 / rt_01~rt_03 / rext_01 / rrel_01）、分货方案 / 补货单 / 复盘报告模板。
规则校验走规则引擎而非向量检索；模板与口径词典作为结构化知识注入。

🩷 异常池（人工终审）：底表口径异常 / DOS 边界冲突 / 多约束无可行解 / 补货单校验不过 / 延误破损超阈 / 差异率>0.5% / 指标恶化或调参冲突 → 升级人工，附上下文摘要与冲突项。

失败 / 降级 / 兜底

触发处理类型
库存/销售计划数据缺失或口径冲突标红缺失字段 → 拉调度组复核，不阻塞其余字段fallback / escalate
DOS 落在 7/14/60 天边界无法自动判定标注边界冲突并转人工确认（物流计划岗）escalate
多约束无可行解（基地仓可发量不足）按可发量约束>时效优先拆分多仓 → 仍不足则输出备选并升级人工fallback / escalate
TMS 物流预警数据未接通按历史运输时效估算，显式标注降级并建议人工复核fallback
补货单 4 项校验不过退回调整并拉人（库存不足/时效超期/字段缺失）escalate
下发后 10 秒内人工撤销回滚物流调度与财务侧写入，补货单回到待下发fallback
WMS 入库差异率>0.5% / 破损率>1%生成差异处理单/异常工单，差异未关闭前不计入可发量escalate
库存同步写入失败自动重试 2 次 → 标记同步异常并通知 ITretry / escalate
复盘指标恶化或多指标冲突以时效达成率优先，拉人审批裁决调参方向escalate

KPI 锚定（链路 → 指标）

分货效率① 缺口识别 + ② 方案编制：分货数据准备/方案编制由约 2.5 天/轮 → 小时级
分仓有货率② 多约束分配（rd_03）+ ④ 库存同步：缺货缓解率 ≥85%
库存周转率② 积压控量 + ⑤ 复盘调参：周转天数同比降幅 ≤10%
新鲜度⑤ 大日期巡检（rd_08）+ ② 新鲜度约束：临期预警前置
物流时效④ 在途跟踪预警：时效达成率 ≥90%
入库差异率④ 入库差异判定（rd_05）：差异率 ≤0.5%、破损率 ≤1%

护栏落点

事实性计算（DOS/备货率/分配求解/校验）走确定性服务 / 本体 / 规则引擎，LLM 不产出数值
写操作（写回分配量 / 下发补货单 / 调参生效）必须人工放行，禁止静默通过；分配量偏离京慧建议量写入前必停
可发量硬约束分配量/补货数量 ≤ 可发量，超约束退回重算
对外下发为合规红线架构层设 HITL 门禁 + 10 秒撤销回滚，不能只写在提示词里
口径一致性待检/合格分开、在途取在途总量、实收才是同步依据——由本体 rdict_01 保证
